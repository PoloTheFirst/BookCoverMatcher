## 4. SVG and animation investigation

**Source (real asset, `pacman-contribution-graph-dark.svg`, 84,944 bytes).**

| Element | Declaration |
| --- | --- |
| `<g id="ghost0..3" transform="translate(0,0)">` ×4 | static translate is the origin; the animated position comes from a child |
| `<animateTransform type="translate">` ×4 | 29 000 ms, 118–145 keyTimes, `calcMode` unset → SMIL's `linear` |
| `<use href="#ghost-…">` ×8 per ghost | direction/eyes/scared sprites, each with `<animate attributeName="visibility">` (31 in total) |
| `<path id="pacman">` | `translate` (145 keys, linear), `rotate` (82 keys, discrete), `fill` (10 keys), `d` (**500 ms** cycle) |
| 20 × `<rect id="c-…">` + `<animate attributeName="fill">` | discrete, one step each at its own keyTime |

No `transform-origin`, no CSS animation, and no clip path, mask or filter touches a ghost: the corner is simply where
those groups sit when their translate animation is not applied.

**Pipeline.** `SmilAnimation.scan()` finds every element that owns SMIL children — the 4 ghost `<g>`, 31 `<use>`, the
Pacman `<path>` and the 20 flashing `<rect>`. `SmilTimeline.detect()` then splits the document: movers are recognised by
their id, each mover's span is found with a small tag-balancing scanner, and the *scenery* is the document with the five
mover spans and every `<animate>` span cut out.

**Verified root cause.** `strip()` removed the highest-offset spans first and skipped any span that overlapped the one it
had just cut. A mover's own `<animate>` children lie *inside* its span, so after the children were cut the parent's span
appeared to overlap them and was skipped — every mover stayed in the scenery. Two consequences:

1. the four ghost groups were rasterised into the still picture at `translate(0,0)` — the stationary sprite in the corner;
2. those same ghosts were drawn a second time by `PacmanCompositor` at their animated positions — the duplicate.

The frame cache, `frameKey`, viewBox and clipping were all innocent: the corner sprite was painted by the *scenery*
bitmap, which is why it appeared on frame 0, never moved, and survived pause.

## 5. Fix implemented

One function, in the transformation layer where the defect lives:

```kotlin
// keep only the outermost spans: a mover contains its own <animate> children
val ordered = spans.filter { ... }.sortedBy { it.first }
val maximal = ArrayList<IntRange>(ordered.size)
for (span in ordered) {
    if (maximal.isNotEmpty() && span.first <= maximal.last().last) continue
    maximal += span
}
for (span in maximal.sortedByDescending { it.first }) out.delete(span.first, span.last + 1)
```

- Files changed: `app/src/main/java/com/bookcovermatcher/core/author/SmilTimeline.kt` (the `strip` helper and its KDoc),
  `app/src/test/java/com/bookcovermatcher/core/author/SmilTimelineTest.kt` (new, 11 tests),
  `app/src/androidTest/java/com/bookcovermatcher/author/PacmanCompositorTest.kt` (one new test),
  `app/build.gradle.kts` (2.6.0 / 223, i.e. unchanged from the 2.6.0 identity — no patch version was introduced),
  `CHANGELOG.md` (the fix merged into the single 2.6.0 entry).
- No coordinate is hardcoded, no overlay covers the sprite, nothing is cropped, no data changed, and the graph's
  dimensions, dark palette and animation rate are untouched. The change removes work (four ghost groups and Pacman are no
  longer rasterised into the scenery) rather than adding any.
