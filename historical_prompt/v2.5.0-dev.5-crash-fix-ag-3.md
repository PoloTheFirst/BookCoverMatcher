## Recognition (`rec`, new)
Preprocessing taken from the model's own `inference.yml`: **BGR**, height **48**, width `ceil(48·w/h)` capped at **320**, right-padded with **0**, `(v/255−0.5)/0.5`, `[1,3,48,320]` f32. Decoding reuses `dict::Charset` (blank 0 / dictionary / optional space), with per-step softmax and a hard **class-count guard**. 10 unit tests.

## ONNX Runtime (`engine`, new)
`ort = "=2.0.0-rc.15"`, `api-20` + `load-dynamic` — **links no runtime**. Two API notes from the earlier session were wrong and are corrected: it is `.build()` (not `.commit()`), and the session builder must be rebound for `with_intra_threads`. One `Environment` + one detector and one recogniser `Session`, reused across images; `run` takes `&mut self`, so inference is **serialized by the borrow checker** (no locks, no unsafe). The CTC head is chosen by matching its width to the dictionary, never by output index.

## Dictionary / class-count verification (the blocker, documented not worked around)

Model emits **18,710** classes; the dictionary in the model's own `inference.yml` has **18,705** entries (extracted file: 18,704) → addressable 18,706/18,707. **4–5 classes are unexplained by any published artefact.** `rec::decode_output` refuses:

```
recogniser outputs 18710 classes but the dictionary maps 18706 (18704 characters + blank + space); refusing to decode
```

No truncation, no padding, no third-party substitution — a 19,053-entry dictionary from a *manga fine-tune* was downloaded, counted and **rejected** as a different model.
