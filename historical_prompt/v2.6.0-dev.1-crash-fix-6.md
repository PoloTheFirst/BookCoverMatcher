## 6. Trace the complete authentication-to-folder-access path

Investigate the actual production implementation, not just isolated helpers.

Trace the following path:

`From OneDrive UI → authentication state → MSAL account → access token acquisition → Graph client → drive discovery → root metadata → root children → folder navigation → JSON parsing → UI state`

For each stage, establish whether it is actually reached during the real-account run.

### A. MSAL authentication

Inspect:

- Whether the account is correctly returned by MSAL.
- Whether the expected account is selected.
- Whether silent token acquisition succeeds after interactive sign-in.
- Whether the requested scopes match the configured delegated permissions.
- Whether the resulting token is valid for Microsoft Graph.
- Whether the application loses the authenticated state when returning from the browser.
- Whether an authentication failure is incorrectly translated into a successful or misleading state.

Never output the token or authentication headers.

### B. Graph drive discovery

Investigate the actual requests and responses for:

- `GET /v1.0/me`
- `GET /v1.0/me/drive`

Establish whether the personal Microsoft account has a discoverable OneDrive drive.

Do not assume that a successful `/me` response means `/me/drive` must succeed.

### C. Root folder access

Investigate:

- `GET /v1.0/me/drive/root`
- `GET /v1.0/me/drive/root/children`

Check whether the application uses the correct drive and item identifiers, constructs the expected URLs, handles response codes correctly, and parses the returned JSON.

### D. Nested folder navigation

Investigate:

- `GET /v1.0/me/drive/items/{item-id}/children`

Check:

- Whether the selected folder's actual item ID is retained correctly.
- Whether the correct drive ID is used where required.
- Whether IDs are safely encoded in URLs.
- Whether navigation accidentally uses a local path instead of a Graph item ID.
- Whether the UI updates after a successful response.
- Whether pagination links are handled correctly.
- Whether the nextLink URL is validated before use.

### E. JSON and UI state

Check:

- Actual Graph response structure.
- Nullable and optional fields.
- Folder-versus-file discrimination.
- Missing or unexpected fields.
- Collection parsing.
- Pagination.
- Loading and error states.
- State updates after navigation.
- Whether an exception is swallowed or converted into an empty folder.
- Whether a previous failure remains visible after a later successful request.

Do not assume a parsing problem is an authentication problem, or vice versa.
