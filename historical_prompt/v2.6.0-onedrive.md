## Part A - The architecture this feature has to fit into (verified)

### A1 - Shape of the application

* Single-module Android app, Kotlin + Jetpack Compose, **no DI framework**: one `MainViewModel` owns
  everything and one immutable `UiState` (`app/src/main/java/com/bookcovermatcher/UiState.kt`) is rendered
  by a handful of screens. State changes go through `_ui.update { ... }`.
* Screens live in `app/src/main/java/com/bookcovermatcher/ui/`: `MainScreen`, `MoreScreen`,
  `WorkbookLibraryScreen`, `WorkbookCommentsScreen`, `WorkbookBrowserPanels`, `WorkbookInsightsPanels`,
  `SavedWorkbookSourceDialog`, `WishlistScreen`, `OnlineSearchPanel`.
* Three runtimes ship in the APK: Kotlin/JVM, a Chaquopy Python bridge (`chrome-lens-py`, OCR path) and a
  Rust OCR core (`native/ocr`, `libbc_ocr.so` + ONNX Runtime). **None of them touches the network.**
* Versions are hard-coded in `app/build.gradle.kts` (`versionCode = 221`, `versionName = "2.5.0"`); this
  release takes them to **222 / `2.6.0`**.

### A2 - How a workbook is read today (the parity target)

```
OpenDocument() picker --> MainViewModel.importWorkbook(uri)      (copy into app storage)
        |                        |
        |                        +--> WorkbookLibrary.import(InputStream, name)
        |                               files/workbooks/<id>.xlsx|.xlsm  +  library.json
        |
        +-- "Use a saved workbook" --> MainViewModel.useSavedWorkbook(id)
                                         |  fail-early parse: openWorkbook(file).close()
                                         +--> StagedWorkbook(file, name, size, sha256)
                                                   |  (the same object the picker produces)
                                                   v
                     WorkbookCommentsController.open(file, sha256, name, importedAt)
                                                   |
                     Zip / JavaZipSource -> WorkbookAnalyzer -> CommentImageScanner
                                                   |        cache: files/comments
                                                   v
                        WorkbookCommentsUi (catalogue, gallery, timeline, health, insights)
```

Everything downstream of `StagedWorkbook` is **file-based**: it opens a `java.io.File`, never a `Uri` and
never a live stream. That is the single most important fact for this feature - see Part C.

### A3 - The library that already exists (where the new button goes)

`app/src/main/java/com/bookcovermatcher/data/WorkbookLibrary.kt`:

* `SavedWorkbook(id, displayName, originalName, format, fileName, sizeBytes, sha256, importedAt,
  lastOpenedAt, pinned, sheetCount, commentCount, imageCount)` - `id` is the identity, never the name.
* `ImportResult` = `Added` / `AlreadySaved` (identical bytes) / `Rejected(message)`.
* `SUPPORTED = setOf("xlsx", "xlsm")` plus a ZIP-signature check; every write is temp-file + rename; a
  corrupt `library.json` is quarantined as `library.json.bad`; a failed import removes its partial copy.
* `library.json` carries `"schema": SCHEMA_VERSION` (**currently 1**) and is read with a strict equality
  check - a schema bump must therefore keep a migration path, or the whole library reads as empty.
* Instantiated once, in `MainViewModel:122`: `WorkbookLibrary(File(app.filesDir, "workbooks"))`.

UI entry points today:

* `WorkbookLibraryScreen.kt:60` - `rememberLauncherForActivityResult(ActivityResultContracts.OpenDocument())`
  calls `vm.importWorkbook(uri)`; the **Import** button is at ~line 80-88 (`GradientButton`).
* The same screen renders the list, rename / pin / remove, a storage panel and per-entry counts.
* `SavedWorkbookSourceDialog.kt` - "Use a saved workbook", the Home/Search source picker. It reads the
  same `ui.savedWorkbooks`, so a OneDrive-imported workbook appears there automatically once it is in the
  library: **no second library may be introduced.**
* `MainViewModel` entry points: `importWorkbook(Uri)` (:577), `useSavedWorkbook(id)` (:526),
  `openSavedWorkbook(id)` (:600), `renameSavedWorkbook` (:627), `setSavedWorkbookPinned` (:633),
  `removeSavedWorkbook` (:639), `refreshSavedWorkbooks()` (:568), `watchSummary(id)` (:618, writes the
  sheet/comment/image counts back into the index after the first parse).

### A4 - What "Rescan" is today (this is what must keep working)

* `WorkbookCommentsScreen.kt:217-222` - a button labelled **Rescan**, `onClick = controller::reload`.
* `WorkbookCommentsController.reload()` (:214) **re-reads the same `File`** that `open(...)` was given; it
  does not know where the file came from. Comments at :195, :223-243 record what survives a rescan: the
  applied mappings, sheet scopes, both filters and the chosen date columns; the per-workbook caches
  (`files/comments`) are cleared; the health and insight reports are rebuilt in place.
* Consequence: a OneDrive-sourced workbook that is stored as a local copy behaves **identically** to an
  imported one, including Rescan, comparison, insights and gallery - with no changes to the controller.

### A5 - What networking exists today (and what does not)

* **One** HTTP client: `app/src/main/java/com/bookcovermatcher/online/HttpJsonClient.kt`. It uses
  `java.net.HttpURLConnection` on purpose (no networking dependency in the app), accepts `https` only,
  connect/read timeouts 10 s / 20 s, and caps bodies at 512 KB for JSON and 2 MB for HTML.
* Failures are translated to `OnlineFailure`: `OFFLINE`, `TIMEOUT`, `RATE_LIMITED`, `SERVER_ERROR`,
  `BLOCKED`, `BAD_RESPONSE` (`core/online/ProductSearchDataSource.kt:8` and neighbours). **There is no
  connectivity monitor anywhere in the app** - "offline" is inferred from `UnknownHostException`,
  `SSLException` or a generic `IOException` *after* a request fails.
* Providers are read with hand-written parsers (Open Library, Google Books, DLsite, Melonbooks HTML); the
  reverse-image provider posts a multipart body (`SauceNaoReverseImageSource`, `MultipartForm`).
* **There is no OAuth, no Microsoft Graph, no MSAL, no token storage and no OneDrive code of any kind**
  (grepped for `onedrive`, `graph.microsoft`, `msal`: zero hits). This feature is greenfield.

### A6 - Storage layout (all under `filesDir`, which the storage panel reports)

| Path | Content |
|---|---|
| `files/workbooks/` | one copy per saved workbook + `library.json` |
| `files/comments/` | per-workbook parse/image caches (`commentsCacheDir`) |
| `files/wishlist/` | profiles, records, originals (`originals/`), thumbnails |

* Rust: `cargo test --test real_models -- --ignored` - **3 passed** with the PP-OCRv6 models.

## Part B - What the owner wants (feature specification)

> "Import an .xlsm/.xlsx from OneDrive into Saved workbooks. The imported online spreadsheet must work the
> same as the offline one, including Rescan. Warn the user when they try to, or already are, accessing /
> importing / rescanning it without internet - including a poor connection, a lost connection, or no
> connection at all."

### B1 - Naming the button (the owner asked for a better name)

| Candidate | Verdict |
|---|---|
| **From OneDrive** | **Recommended.** Short enough to sit beside `Import` without re-wrapping the row, and it names the source the way the screen already speaks ("Saved workbooks", "Use a saved workbook"). |
| `Import from OneDrive` | Unambiguous but long: use it as the **dialog title** and the first-run explainer, not as the button. |
| `OneDrive...` | Conventional but ambiguous - a bare provider name reads like a filter, not an action. |
| `Add from cloud` / `Cloud workbook` | **Rejected:** implies several providers, and only one will exist. |
| `Link a workbook` | **Rejected:** suggests a live link, which contradicts the local-copy model in B3. |

So: keep the existing **Import** button for local files, add **From OneDrive** beside it, and mark library
rows that came from OneDrive with a small `OneDrive` badge plus their sync state (B5). The Home/Search
picker needs no new button - it lists the same library, which is the invariant `SavedWorkbookSourceDialog`
was written around.

### B2 - The four flows

1. **Import.** `From OneDrive` -> pre-flight connectivity check -> (sign-in if required, see Part C) ->
   browse/search the account, filtered to `.xlsx`/`.xlsm` -> pick one -> download with a determinate
   progress indicator and a working Cancel -> validate exactly as `WorkbookLibrary.import` does today
   (extension + ZIP signature + size) -> `ImportResult` toast (`Added` / `AlreadySaved` / `Rejected`) ->
   offer "Use it now", which stages it through `useSavedWorkbook`, so Home/Search keep their single scan
   path.
2. **Open / read.** Unchanged: the library copy is a plain file, so `openSavedWorkbook` and the whole
   `WorkbookCommentsController` pipeline run untouched.
3. **Rescan.** For an online-sourced entry: always re-read the **local copy** first (this must keep
   working with no network), then - only if the network is usable and the entry carries a remote
   identity - ask the service whether the file changed (ETag / cTag / lastModifiedDateTime / size), and
   either update silently (if the owner enables auto-update) or offer **Update from OneDrive**.
4. **Offline, at any point.** Warn, keep the local copy usable, and never discard the user's intent.

### B3 - Parity table (the acceptance criterion)

| Action | Local workbook | OneDrive workbook, online | OneDrive workbook, offline |
|---|---|---|---|
| Open, catalogue, gallery, timeline, health, insights | yes | yes | **yes** |
| Rescan (re-parse the bytes we hold) | yes | yes | **yes** |
| Rescan (pull a newer version) | n/a | yes | **no - warned, local copy still re-parsed** |
| Compare two workbooks | yes | yes | yes |
| Rename / pin / delete | yes | yes (delete says whether the cloud copy is kept) | yes |
| Use as scan source (Home/Search) | yes | yes | yes |

**Design consequence:** the workbook must be **materialised as a local file** at import time and only ever
*refreshed* from the network. Streaming a remote workbook on every read would break Rescan, comparison and
insights, rewrite `WorkbookCommentsController` for no gain, and make the offline column impossible.

### B4 - Connectivity handling (the part that is easy to get wrong)

The app has **no connectivity monitor today** (A5), so this feature introduces the first one:

* One injectable seam, e.g. `interface ConnectivityMonitor { val online: StateFlow<Boolean>; fun
  isUsableNow(): Boolean }`, backed by `ConnectivityManager` + `NetworkCapabilities`
  (`NET_CAPABILITY_INTERNET` **and** `NET_CAPABILITY_VALIDATED`). Injected, so tests drive it; never call
  `ConnectivityManager` from a composable or a repository.
* **Do not claim to measure speed.** `NET_CAPABILITY_VALIDATED` detects "no usable route" and captive
  portals, not a slow link. "Poor connection" is *inferred from behaviour* - a connect/read timeout or
  stalled reads - and reported as "slow or unstable", never as a measured figure.
* Keep four states apart and never merge them: **no connection**, **connection but OneDrive unreachable or
  throttled** (HTTP 429/503), **slow/unstable**, **signed out / token expired**.
* Pre-flight before import and before a network Rescan; never pre-flight local-only actions.
* If the connection drops mid-download, keep the partial file out of `files/workbooks` (write `*.part`,
  delete on failure - the library already uses temp-file + rename), report it and offer Retry.
* Every warning names the workbook and the action, says what still works, and offers the local fallback.

Suggested copy (project tone: sentence case, no exclamation marks):

| Moment | Message |
|---|---|
| Button tapped, no connection | "No internet connection. OneDrive workbooks can only be imported online. Workbooks you already saved still open and rescan offline." |
| Connection lost during import | "The connection was lost while downloading <name>. Nothing was saved. Retry when you are back online." |
| Rescan, no connection | "Offline: showing the copy saved on this device. The workbook was not checked for changes on OneDrive." |
| Rescan, slow/unstable | "OneDrive took too long to answer. The saved copy was rescanned instead." |
| Workbook moved or deleted in OneDrive | "This workbook is no longer in OneDrive. The saved copy still opens; rescan it locally, or import the file again." |
| Token expired | "Your OneDrive sign-in expired. Sign in again to check for changes." |
| Newer version found | "A newer version is on OneDrive (<size>, <date>). Update the saved copy? The current copy stays until the new one is verified." |

### B5 - What a library row shows

`Synced <date>` / `Offline copy` / `Signed out` / `Last check failed` - one short line, plus the existing
sheet/comment/image counts. Never replace the counts with sync text, and never hide the `originalName`
line: two workbooks can share a display name, which is exactly why that line exists.

## Part C - How it could be built (options, data model, risks)

### C1 - Three options

| | **A - Storage Access Framework** | **B - Microsoft Graph + OAuth** | **C - Graph plumbing, minimal UX (recommended)** |
|---|---|---|---|
| What the user does | `OpenDocument()` with the OneDrive `DocumentsProvider` chosen; the system picker browses OneDrive | In-app browse/search, then download | In-app recent-files + search by name, then download |
| Auth | none | App registration (client ID), Authorization Code + PKCE, scopes `Files.Read` + `offline_access` | same as B |
| New dependencies | none | MSAL-Android (MIT) or a hand-written PKCE flow on `HttpJsonClient`; Keystore-backed token storage | same as B |
| Change detection | impossible | `eTag` / `cTag` / `lastModifiedDateTime` / `size` from `/me/drive/items/{id}` | yes |
| Rescan offline | local copy only (indistinguishable from a local import) | local copy, then freshness check | local copy, then freshness check |
| Honest effort | ~1-2 days, low risk | ~2 weeks | ~2 weeks, best parity with B2/B3 |
| Verdict | cheap but **cannot satisfy B2 flow 3** (no remote identity, no refresh) | satisfies everything, more UI to build | satisfies everything with less UI |

**Recommendation: C.** Model the network behind one seam so the offline matrix is testable and a second
provider would not need a second library:

```kotlin
interface RemoteWorkbookSource {
    suspend fun recent(query: String?): List<RemoteItem>      // id, name, size, modifiedAt, eTag
    suspend fun probe(id: String): RemoteState               // Present(eTag, size, modifiedAt) | Gone
    suspend fun download(item: RemoteItem, sink: OutputStream): DownloadOutcome  // cancellable, progress
}
```

`GraphWorkbookSource` is the real implementation; `FakeWorkbookSource` drives unit and instrumented tests
(no network, no account, deterministic). Nothing above this interface may know about HTTP.

### C2 - Data model and the migration that must not lose data

`SavedWorkbook` (A3) gains: `origin` (`LOCAL` | `ONEDRIVE`), `remoteId`, `remotePath` (display only),
`eTag`, `remoteModifiedAt`, `remoteSize`, `lastSyncedAt`, `lastCheckedAt`.

`library.json` moves to `"schema": 2`. **This is the one place that can destroy user data:**
`WorkbookLibrary.readAll()` returns an empty list when the stored schema is not exactly `SCHEMA_VERSION`,
so a naive bump makes every saved workbook disappear (the copies stay on disk, but the index reads empty).
The plan must include: read schema 1 and treat every entry as `origin = LOCAL`; write schema 2; keep a test
that opens a real v1 `library.json` and asserts the entries survive with `origin = LOCAL`.

### C3 - Rescan semantics, decided explicitly

| Entry | Network | What Rescan does |
|---|---|---|
| `origin = LOCAL` | any | `WorkbookCommentsController.reload()` - exactly as today |
| `origin = ONEDRIVE` | offline | `reload()` on the saved copy + the B4 "Offline" message |
| `origin = ONEDRIVE` | online, unchanged | `probe()` says the eTag matches -> `reload()` + "Already up to date" |
| `origin = ONEDRIVE` | online, changed | "Newer version found" prompt -> download to `*.part` -> validate -> replace -> `reload()` |
| `origin = ONEDRIVE` | online, remote gone | keep the copy, say so (B4), `reload()` locally |

The controller stays untouched: the ViewModel sequences "maybe refresh the file, then `reload()`". That is
what keeps the 986 JVM tests and the rescan behaviour (`RescanStateTest`) intact.

### C4 - Security

* Refresh/access tokens through Android Keystore-backed storage (e.g. `androidx.security-crypto`, Apache-2.0)
  - **never** in `library.json`, never in logs, never in a toast or an error message.
* Minimal scopes; no background sync; sign-out clears tokens and leaves the workbooks readable offline.
* No client secret in the APK (public client + PKCE only). Redirect URI follows the MSAL Android pattern
  (`msal<client-id>://auth`).
* Reuse `HttpJsonClient` discipline for anything hand-rolled: HTTPS only, timeouts, byte caps - but note
  its current caps (512 KB JSON / 2 MB HTML) are far too small for a workbook, so the download path needs
  its own streaming code with a **workbook size cap chosen by the owner** and progress reporting.

### C5 - Licensing and dependency gate

MSAL-Android is MIT and `androidx.security-crypto` is Apache-2.0: both are compatible with the project's
`GPL-3.0-or-later`, but each needs a row in `THIRD_PARTY_NOTICES.md`, and the notices file is packaged into
the APK (`assets/licenses/`). `python tools/check-licenses.py --refs --history` must still pass, and the
project's rule holds: project code is GPL, third-party stays third-party.

### C6 - Risks the plan must name

1. Personal Microsoft accounts vs work/school tenants (different consent and, sometimes, conditional-access
   blocks that cannot be solved in code).
2. Throttling: Graph answers 429 with `Retry-After`; the UI needs to say "try again shortly" rather than
   "failed".
3. Large workbooks: the owner's real catalogue file is ~40 MB; download needs streaming, progress, cancel
   and a size cap.
4. Blocked/signed-out states must never make the library unusable.
5. The `*.part` file must never be visible to the library as a workbook.
