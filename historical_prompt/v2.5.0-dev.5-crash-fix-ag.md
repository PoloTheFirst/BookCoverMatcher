## 1. Root cause

**Reproduced (verified):** the release and debug builds are signed with **different certificates** — `CN=Tin Yan To` (release) vs `CN=Android Debug` (debug) — even though `app/build.gradle.kts` declares `release { signingConfig = signingConfigs.getByName("debug") }`. So `app-release.apk` came from the *signed-APK wizard* with your own key, not from `assembleRelease`. Installing it over an existing debug-signed install fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`, which OEM installers routinely surface as a generic "App not installed / problem parsing the package" dialog.

**Not reproducible (so not claimed):** the literal parse message can otherwise only come from (a) a device **below Android 8.0 / API 26** (`minSdk 26`) or (b) a **truncated copy** of the 182 MiB file. Both live outside the repo. The artifact itself parses: the on-device installer got as far as the signature check, which is impossible with a malformed manifest.
