## A. Implementation summary

Six issues, all resolved inside the existing architecture:

1. **Rescan now refreshes every Insights function.** `WorkbookCommentsUi.reloadingForRescan()` drops only what
   came from the old bytes (catalog, health, analytics, both timelines, the mapping preview) and keeps every
   user choice; `analysisLoaded()`/`reloadFailed()` settle the busy state; and
   `WorkbookCommentsController.apply()` rebuilds the catalog and all five functions (`refreshInsights()`) as
   soon as a rescan finishes while the Insights directory is open, re-previewing the Fields draft against the
   new tables. Leaving and re-entering the directory is no longer part of the path.
2. **The global "Sheets" button is gone** from the shared preview header. The worksheet picker is still opened
   from the sections that filter by worksheet (Comments / Images / Catalogue) through `SheetSelector`; no
   worksheet feature, mapping or scope was removed, and no empty gap is left in the header.
3. **The Rescan button now uses the Import button's blue**: the same `Palette.NavyGradient` token (not a new
   colour), same size, typography and enabled/disabled behaviour; Back stays grey.
4. **Default Order detection and manual selection** both existed, but a manual mapping could be silently
   reverted: `applyMapping()` stored it only in the draft. `WorkbookCommentsUi.appliedMapping` now keeps it in
   the state, in precedence order **saved profile → applied (manual) mapping → detected headers**;
   `isDetectedMapping` and `mappingSourceLabel` distinguish the three on the Fields screen, picking "Detected"
   or a profile clears the manual mapping, and deleting the active profile returns to detection. Detection
   itself is unchanged (aliases only, any header/language/position, no hard-coded `通し番号`).
5. **Linked cells survive parsing.** New `core/excel/comments/SheetLinks` reads `<hyperlinks>` plus the
   worksheet's `.rels`: external targets from the relationship, internal ones from `location`, ranges expanded
   within a bound, unresolvable references dropped. `CatalogueRecord.links` keeps them **by source column**, so
   a cell can never show its neighbour's link, and the displayed value is untouched.
6. **The table has a cell dialog.** Tapping a cell opens a centred dialog with its value and three stacked
   actions — **Copy** (the displayed text, via the system clipboard, with feedback), **Open Link** (only for a
   stored, followable link: `http(s)`/`mailto` to the browser, `Sheet!Cell` into the app's own source view) and
   **Back** — dismissed by Back, the back gesture or a tap outside the card. Linked cells are drawn in the
   accent colour and underlined. Cell identity is worksheet + source row + source column, never screen
   position.

## C. Root causes and corrections

**1. Rescan did not refresh the Insights functions.**
*Original behaviour:* pressing Rescan with Insights open cleared the reports and showed "Nothing to report
yet." until the user left the directory and came back.
*Cause:* `WorkbookCommentsController.reload()` cancelled the job and cleared `catalog/health/analytics/timelines`,
but only `showSection(INSIGHTS)` ever called `refreshInsights()`. Staying in the section meant nothing rebuilt
the derived results from the new `analysis`.
*Correction:* a rescan now runs through `reloadingForRescan()` (drop derived data, keep choices, raise the
reading state) and `analysisLoaded()`; after a successful scan `apply()` re-previews the Fields draft and calls
`refreshInsights()` whenever `section == INSIGHTS`. `reloadFailed()` clears the busy state on error. Repeated
rescans cannot overlap (`job?.cancel()`, `insightsBusy` guard) and cannot duplicate records, because the
catalog is rebuilt from the analysis rather than appended to.
*Verification:* `RescanStateTest` (4) — old results dropped, every choice kept, rebuild produces the new
catalog with the user's gallery/timeline filters applied, busy/error transitions; plus the build.

**2. The global Sheets button.**
*Cause:* `CommentsHeader` rendered one "Sheets" button above all four sections, though only Comments/Images/
Catalogue filter by worksheet — it read as a global filter it never was.
*Correction:* the button and its spacer were removed; the picker stays reachable through `SheetSelector` in the
sections that use it, so `openSheetPicker`, `sheetPickerOpen` and `sheetSearch` are still required and were
kept.

**3. Rescan button colour.**
*Correction:* `Palette.GreyGradient` → `Palette.NavyGradient`, the exact token the Saved-workbooks **Import**
button uses; content colour, width, height and enablement untouched.

**4. Manual mapping reverted to detection.**
*Cause:* `applyMapping()` sent the profile to `refreshInsights(profile)` but stored only `activeProfile`
(null when the mapping was not saved as a profile). The next `refreshInsights()` — a scope change, a profile
delete, a rescan — recomputed `chosen` as "saved profile else detected", so the user's manual mapping quietly
disappeared. The Fields screen also showed "Detected" as active, which was untrue.
*Correction:* `WorkbookCommentsUi.appliedMapping` keeps the applied profile; `appliedProfile()` and
`refreshInsights()` resolve **profile → manual → detected**; `selectProfile(null)`/"Detected", saving a profile
and deleting the active profile clear it; `isDetectedMapping`/`mappingSourceLabel` drive the chip and the
informational line; `startMapping()` seeds the draft from the same precedence.
*Verification:* `CellPeekAndMappingTest` (5, the precedence half) and the rescan test that a manual mapping
survives `reloadingForRescan`/`analysisLoaded`/`reloadFailed`.

**5. Hyperlinks were lost.**
*Cause:* the parser read only cell values; `<hyperlinks>` and the worksheet's `.rels` were never touched, so
the table could not know a cell was linked.
*Correction:* `SheetLinks.read(zip, sheetPath)` (pure `parse(xml, rels)` under it) → `CatalogueRecord.links`
by source column; `CatalogueReader.read` attaches them; `TableCell` draws them underlined; the cell dialog and
its two actions use the same object.
*Verification:* `SheetLinksTest` (7, incl. a full package and the real `doujin.xlsx` whose circle column really
links to a shop search).

**6. No way to copy a cell or follow its link.**
*Correction:* `CellPeekUi` + `peekCell()`/`closeCellPeek()` in the state, `peekCell`/`copyPeekedCell`/
`openPeekedLink` in the controller, and `CellPeekDialog` in the UI (Copy / Open Link / Back, outside-tap
dismissal).
*Verification:* `CellPeekAndMappingTest` (3 of its 5 tests cover the dialog's identity, value and link rules);
the clipboard/intent calls are Android-side and were compiled, not unit-tested (§G).

## G. Outstanding issues

1. **No device or emulator pass.** The cell dialog's clipboard write and browser intent, the outside-tap
   dismissal, the underline styling and the new Rescan colour are compiled and their state is unit-tested, but
   no screen was tapped through; `app/src/androidTest` (OCR + live catalogue) needs hardware and was not run.
2. **The copy/link actions are not unit-tested** — they need an Android `Context`; the state they read
   (`CellPeekUi`, `CellLink`) is fully tested instead.
3. **Only `Sheet!Cell` internal links are followed.** A defined name, a `file://` path or a scheme with no
   handler keeps its destination in the dialog but offers no Open Link (deliberate, documented).
4. **A collapsed `ref` range larger than 1024 cells** applies to its first cell only, so a whole-column link is
   not expanded into a huge map (deliberate bound, documented).
5. **A manual mapping is session state**, not persisted: it survives rebuilds and rescans, but reopening the
   app returns to the detected mapping unless the user saved a profile. That matches the existing profile
   architecture; saving it automatically would require a new stored decision.
6. **Recommended follow-up:** an on-device pass over the preview header, the Catalogue table and the dialog; a
   Compose UI test module if the project accepts that dependency; and (optionally) persisting the last manual
   mapping per workbook.
