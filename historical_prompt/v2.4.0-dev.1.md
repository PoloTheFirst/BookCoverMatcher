## 5. Primary feature — navigate from an image to its source worksheet row and cell

### 5.1 Goal

Allow users to determine where an image or catalogue record originates in the source workbook and navigate to the corresponding worksheet and cell reference inside BookCoverMatcher.

This is the worksheet-to-source-row/cell navigation feature explicitly deferred from v2.3.1 to v2.4.0.

The feature must use verified associations from the existing workbook parser. It must never guess a row or cell from image order, filename, media index, or approximate visual position.

### 5.2 Supported entry points

Inspect and implement the most useful entry points in the existing UI, including where appropriate:

- An image in the Images browser.
- An image in Workbook Comments.
- A linked image record in an image detail or preview screen.
- A catalogue record.
- A search result representing a catalogue record or linked image.

Use the existing navigation architecture. Do not create parallel screens or a second workbook-loading pipeline.

### 5.3 Source-location information

Where the parser has verified the association, expose the relevant information:

- Workbook identity.
- Worksheet identity.
- Cell reference, such as `D128`.
- Associated image identity or catalogue record identity where available.

Use actual worksheet names and cell references from the workbook structure.

Handle worksheet names containing spaces, punctuation, Unicode, and trailing spaces without corrupting their underlying identity.

### 5.4 Navigation behaviour

When the user activates a source-location action:

1. Confirm that the referenced workbook is available.
2. Open or reuse the correct workbook context.
3. Select the source worksheet.
4. Navigate to or highlight the corresponding cell or record in an appropriate in-app source-location view.
5. Clearly indicate the selected source location.
6. Allow the user to return to the previous image, catalogue, or search context.

If no suitable worksheet cell-viewing component exists, inspect the architecture and introduce the smallest appropriate in-app source-location view.

Do not claim that a cell has been selected if the UI only displays a cell-reference label.

Do not modify the original workbook to add highlights or navigation metadata.

### 5.5 Unavailable and ambiguous associations

Distinguish between:

- A verified image-to-cell association.
- An unreferenced media file.
- An unresolved association.
- A catalogue record whose source location is unknown.
- A missing or unavailable workbook.

For unreferenced or unresolved images, do not invent a destination. Explain that a reliable source location is unavailable.

If multiple candidate locations exist, present only candidates that the parser can establish. Never silently choose an arbitrary candidate.

### 5.6 Data model and parser requirements

Inspect existing models before adding fields.

- Reuse existing worksheet and cell-reference information.
- Keep stable internal identities separate from display labels.
- Do not use filenames or display names as unique workbook identifiers.
- Do not introduce a duplicate parser or duplicate association database.
- Preserve unknown values as unknown rather than substituting zero or a fabricated cell reference.
- Avoid reparsing the workbook on every navigation action when the necessary parsed data is already available.

Add fields or models only where the existing architecture cannot represent the required information.

### 5.7 Required regression tests

Add tests for:

- Navigating from a linked image to its verified source cell.
- Navigating from a catalogue record to its source row.
- Worksheet names containing spaces and Unicode.
- Worksheet names with trailing spaces.
- Switching between workbooks with similar display names.
- Unreferenced images.
- Unresolved associations.
- Missing or removed workbooks.
- Returning to the previous screen and restoring appropriate state.
- Preventing navigation to fabricated or stale locations.

Test source-location mapping independently of the UI, and add UI/navigation tests where the project supports them.
