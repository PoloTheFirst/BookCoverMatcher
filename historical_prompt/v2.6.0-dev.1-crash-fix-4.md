## 4. Investigate connectivity preflight

Inspect the existing `ConnectivityMonitor` and all callers.

The architecture previously specified that connectivity monitoring uses:

- `ConnectivityManager`
- `NetworkCapabilities`
- `NET_CAPABILITY_INTERNET`
- `NET_CAPABILITY_VALIDATED`

Understand the intended semantics and confirm that the implementation follows them.

Investigate the following cases:

1. No active network.
2. Active Wi-Fi without validated internet access.
3. Active mobile data with validated internet access.
4. Wi-Fi connected but captive portal or sign-in required.
5. Network switching between Wi-Fi and mobile data.
6. Network becoming available immediately after a failed preflight.
7. Network becoming unavailable during authentication.
8. Network becoming unavailable during Graph requests.
9. A valid network where Microsoft Graph is temporarily unreachable.
10. A valid network where authentication fails for a non-connectivity reason.

Check whether:

- The app uses a stale connectivity snapshot.
- The monitor observes the wrong network.
- The monitor checks connectivity too early.
- A transient `null` network or capability result is incorrectly treated as permanent offline state.
- A valid connection is rejected unnecessarily.
- Connectivity is checked only once and never re-evaluated.
- Network callbacks or lifecycle changes leave stale state.
- The same generic offline error is used for unrelated failures.

Do not remove the `NET_CAPABILITY_VALIDATED` check merely to make the UI proceed. Do not treat `NET_CAPABILITY_INTERNET` alone as proof that Microsoft Graph is reachable.

## 6. Investigate Microsoft Graph connectivity and errors

Inspect the actual Graph endpoint and request sequence used by the application.

- Required delegated permissions.

- Whether a failed request is retried incorrectly.

At minimum, distinguish the following categories:

| Failure | Expected classification |
|---|---|
| No network or no validated internet | Connectivity unavailable |
| DNS resolution failure | Network/DNS failure |
| Connection timeout | Connection timeout |
| TLS/certificate failure | Secure connection failure |
| HTTP 401 | Authentication/token problem |
| HTTP 403 | Permission/access denied |
| HTTP 404 | Resource not found |
| HTTP 429 | Graph throttling |
| HTTP 5xx | Microsoft service/server failure |
| Invalid or unexpected response | Response/data error |
| User cancellation | Cancelled, not offline |
| Local disk full | Local storage failure |
| Workbook validation failure | Invalid/unsupported workbook |

Use the existing `GraphFailures` abstraction and tests where appropriate. Do not duplicate existing error-classification logic without a clear reason.

Do not log sensitive response headers, bearer tokens, authentication codes, or personal workbook contents.
