# BookCoverMatcher — v2.5.0-dev.5 Complete Rust OCR Migration

## 1. Objective

Complete the partially implemented Rust OCR migration in BookCoverMatcher.

The objective is to replace the application's existing Python-based OCR implementation (`chrome-lens-py`, executed through Chaquopy) with a fully integrated native Rust OCR implementation using PP-OCRv6 Medium ONNX models and ONNX Runtime.

**This is an OCR-only migration. It is not an application rewrite.**

The existing Android application, written in Kotlin and Jetpack Compose, must remain the application framework. Rust is responsible for implementing the OCR processing previously performed by Python. Kotlin continues to own the Android UI, application lifecycle, image acquisition, user interactions, and integration with the rest of the application.

The final application must perform OCR through the native Rust implementation without requiring Python or Chaquopy for OCR.

Do not claim the migration is complete until the native OCR implementation has been integrated, tested on an Android device, and demonstrated to work with the actual PP-OCRv6 Medium models.

## 3. Strict migration boundary

### 3.1 What Rust replaces

Rust must replace the Python OCR processing currently performed by `chrome-lens-py`.

This includes the OCR-specific responsibilities that the existing Python implementation performs, such as:

- Image preprocessing for OCR.
- Text detection.
- Text-region geometry processing.
- Perspective transformation and cropping.
- Text recognition.
- CTC decoding.
- Text-region ordering.
- OCR result construction and normalization.
- Any OCR-specific postprocessing currently implemented in Python.

- Jetpack Compose UI.

- Image selection and Android URI handling.
- Permission handling.

- Coroutine lifecycle and cancellation integration.
- OCR result presentation.
- Integration with existing search and matching workflows.
- Application-level state management.
- Existing persistence and profile management.
- Existing error presentation and navigation.
