# 3. Insights Rescan Must Refresh All Function Results

## 3.1 Current behavior

When the user navigates to the Insights directory and clicks the Rescan button at the top, the results of its functions are not loaded or refreshed correctly.

Affected functions:

- Health.
- Analytics.
- Gallery.
- Timeline.
- Fields.

The results only become available after the user navigates to another directory and then returns to Insights.

## 3.2 Expected behavior

Clicking Rescan must refresh all relevant data and make updated results available immediately, without requiring the user to leave and re-enter the Insights directory.

## 3.3 Implementation requirements

1. Trace the complete rescan lifecycle, from the UI button callback through the scanning/import pipeline, repositories, data sources, ViewModels, state holders, and UI collectors.
2. Identify why the current rescan operation does not trigger the necessary data refresh while Insights remains visible.
3. Ensure that a successful rescan invalidates or updates all relevant cached data and derived results.
4. Ensure Health, Analytics, Gallery, Timeline, and Fields receive the refreshed data.
5. Ensure the UI observes the updated state and renders the results without requiring navigation.
6. Ensure dependent calculations and worksheet information are recalculated where necessary.
7. Preserve existing user preferences, mappings, filters, and persisted selections during rescanning.
8. Avoid unnecessarily resetting unrelated UI state or scroll positions.
9. Prevent duplicate scans and conflicting refresh operations.
10. Handle loading, success, empty, and error states clearly.

Do not solve this merely by forcing navigation away from and back to Insights. Correct the underlying refresh and state-invalidation mechanism.

## 3.4 Verification

Test the following sequence:

1. Open a workbook.
2. Navigate to Insights.
3. Open or inspect the available functions.
4. Change the underlying workbook data where appropriate.
5. Return to the Insights directory.
6. Click Rescan.
7. Verify that all five affected functions receive and display the updated results without leaving Insights.

Also verify that repeated rescans do not create duplicate records, stale results, or inconsistent mappings.

# 6. Default Order Header: Automatic Detection and Manual Selection

## 6.1 Current behavior

The Default Order mapping exists as a concept, but users need more control over which source column is used.

## 6.2 Expected behavior

The application must support both:

- Automatic detection of a likely Default Order column.
- Manual selection or reassignment by the user.

Automatic detection must remain available and behave consistently with the detection mechanism used for other mapped headers.

## 6.3 Implementation requirements

1. Retain automatic detection of a likely Default Order column.
2. Allow the user to inspect the detected mapping.
3. Allow the user to manually assign a different source column.
4. Allow the user to change the selected column later.
5. Allow the user to clear or unset the mapping.
6. Clearly distinguish automatically detected mappings from manually selected mappings where appropriate.
7. Do not hardcode `通し番号`, `Serial Number`, or any other specific header.
8. Support arbitrary header names, languages, column positions, and workbook structures.
9. Validate the selected column and preview representative values before saving.
10. Persist the selection using the existing workbook and mapping-profile persistence architecture.
11. Handle renamed, removed, or otherwise stale columns safely.
12. Ensure manual selection takes precedence over automatic detection until the user explicitly resets or changes the mapping.

## 6.4 Timeline integration

Continue applying Default Order as the secondary ordering key when multiple records have equal Published or Acquired dates.

The ordering rules remain:

1. Primary: chronological date.
2. Secondary: Default Order ascending.
3. Final fallback: deterministic source identity or original source order where available.

Changing the mapping must update Timeline ordering without corrupting the primary chronological order.

# 7. Preserve Linked-Cell Characteristics in Table Preview

## 7.1 Current behavior

Some spreadsheet cells contain hyperlinks or other linked-cell characteristics, but these relationships are not adequately represented in the table preview.

## 7.2 Expected behavior

The table preview must preserve and visibly represent linked-cell information so that users can recognize linked values and follow their destinations.

## 7.3 Implementation requirements

1. Inspect the spreadsheet parsing pipeline to determine how hyperlink information is currently represented or lost.
2. Preserve cell hyperlink metadata when parsing the workbook.
3. Associate hyperlink metadata with the correct worksheet, row, and column.
4. Preserve the displayed cell value separately from its hyperlink destination.
5. Represent linked cells visually in the table preview so users can distinguish them from ordinary cells.
6. Make linked cells interactive.
7. When a linked cell is activated, use its actual stored hyperlink destination.
8. Do not fabricate URLs from displayed text.
9. Do not treat ordinary text that resembles a URL as a hyperlink unless the source workbook actually provides a supported link or an explicitly supported automatic-link rule applies.
10. Handle external hyperlinks, internal workbook links, missing destinations, and unsupported link types safely.
11. Preserve the source workbook unchanged.

Where practical, support both:

- External website hyperlinks.
- Internal workbook or worksheet hyperlinks.

For internal workbook links, use the application's existing navigation capabilities where possible. Do not treat an internal workbook reference as an external website.

# 8. Table Preview: Cell Value Dialog and Copying

## 8.1 Current behavior

Users cannot conveniently copy individual cell values from the table preview or interact with linked-cell destinations through a consistent cell-selection interface.

## 8.2 Expected behavior

When a user clicks a cell in the table preview, display a dialog in the middle of the screen.

The dialog must display the selected cell's value and provide the following vertically arranged buttons:

1. Copy.
2. Open Link.
3. Back.

The Open Link button is conditional and should only be available when the selected cell has a valid supported hyperlink destination.

## 8.3 Dialog layout

The dialog should:

- Appear centrally on the screen.
- Display the selected cell's value clearly.
- Preserve line breaks and readable formatting where appropriate.
- Handle long values without overflowing the screen.
- Support horizontal and vertical scrolling for long content if necessary.
- Keep the available actions vertically arranged.

Button order:

| Position | Button | Behavior |
|---|---|---|
| Top | Copy | Copy the selected cell's displayed value to the system clipboard |
| Middle | Open Link | Open the actual hyperlink destination; only show or enable when a valid supported link exists |
| Bottom | Back | Close the dialog |

When no hyperlink exists, do not display a misleading Open Link action. The remaining actions must retain their intended behavior.

## 8.4 Copy behavior

When the user clicks Copy:

1. Copy the selected cell's displayed value to the system clipboard.
2. Preserve the complete text, including meaningful spaces and line breaks.
3. Do not copy the hyperlink URL instead of the displayed value.
4. Do not modify the original cell value.
5. Provide appropriate feedback that the copy action succeeded.

For an empty cell, handle the action sensibly without copying an unrelated value.

## 8.5 Open Link behavior

When the selected cell has a valid supported hyperlink:

1. Display the Open Link button between Copy and Back.
2. Open the actual stored destination when the user clicks it.
3. Use the appropriate platform intent or existing navigation mechanism.
4. Validate and handle unsupported or malformed destinations safely.
5. Do not infer a destination from the displayed cell text.

For internal workbook links, use internal navigation where supported instead of attempting to open them as websites.

## 8.6 Dialog dismissal

The dialog must also be dismissible when the user clicks outside its bounds, on the empty area surrounding the prompt.

The Back button must remain available even though outside-click dismissal is supported.

Ensure:

- Clicking inside the dialog does not accidentally dismiss it.
- Clicking outside dismisses it.
- The Back button closes it.
- System Back behavior remains consistent with the application's dialog conventions.
- Accessibility and touch interaction remain appropriate.

## 8.7 Cell selection and identity

Ensure the selected cell is correctly identified by its workbook, worksheet, row, and column.

Do not rely solely on its displayed position if sorting, filtering, or scrolling can change the displayed order.

The selected value and hyperlink metadata must always correspond to the same underlying source cell.
