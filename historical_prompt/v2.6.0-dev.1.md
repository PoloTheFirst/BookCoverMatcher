## 1. Objective

Implement OneDrive workbook importing and refreshing in BookCoverMatcher.

OneDrive-imported workbooks must become ordinary entries in the existing Saved workbooks library. They must use the existing workbook opening, parsing, catalogue, gallery, timeline, health, insights, and Rescan workflows.

OneDrive is a read-only remote source. The app downloads workbooks to local storage. It must never modify the original OneDrive files.

## 2. Confirmed implementation decisions

These decisions are final for this development version.

| Area | Decision |
|---|---|
| Integration approach | Option C: Microsoft Graph plumbing with focused UI |
| Microsoft accounts | Personal Microsoft accounts only |
| Azure app registration | Required; create and configure one |
| Remote refresh | Only when the user explicitly selects Rescan |
| Maximum workbook size | No arbitrary application-level size limit |
| OneDrive browsing | Folder browsing, including nested folders |
| Deleting a saved entry | Delete only the local entry and local copy; retain the OneDrive original |
| Upload/write-back | Never |

### Important interpretation of unlimited file size

Do not introduce an arbitrary application-level maximum workbook-size limit.

This does not mean ignoring device storage, filesystem limits, network failures, Microsoft Graph restrictions, or insufficient disk space.

Downloads must stream to disk. The app must handle storage exhaustion, interrupted transfers, cancellation, and validation failures safely. Never load an entire workbook into memory just to download it.

## 6. Rescan and remote refresh

Remote refresh happens **only when the user explicitly chooses Rescan**.

Opening a workbook must always use its local copy and must never trigger an automatic OneDrive refresh.

### Rescan behaviour

| Source/state | Required behaviour |
|---|---|
| Local workbook | Existing local Rescan behaviour |
| OneDrive workbook, offline | Reload local copy and show offline warning |
| OneDrive workbook, online and unchanged | Probe metadata, reload local copy, report up-to-date |
| OneDrive workbook, changed | Ask whether to update |
| User declines update | Keep current local copy and complete local Rescan |
| User accepts update | Stream to temporary file, validate, safely replace, then reload |
| Remote file missing | Keep local copy and report remote item unavailable |
| Sign-in expired | Keep local copy and ask user to sign in again to check remotely |
| Remote timeout or service failure | Keep local copy and complete local Rescan where possible |

Use ETag or equivalent remote metadata to detect changes. Also retain remote modified time and size where available.

Do not automatically overwrite a local workbook.

Do not modify the OneDrive original.

### Safe update sequence

1. Probe the remote item.
2. Compare remote metadata with the saved metadata.
3. If unchanged, perform the existing local reload.
4. If changed, ask for confirmation.
5. If accepted, download to a temporary file.
6. Validate the temporary file.
7. Replace the local copy safely.
8. Update saved remote metadata.
9. Reload the workbook through the existing controller workflow.

If any step before replacement fails, retain the previous local copy and metadata.
