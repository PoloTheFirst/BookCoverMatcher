# BookCoverMatcher — v2.5.0-dev.5-crash-fix-9

## Objective

Improve **PaddleOCR accuracy** in the real Online → READ THE COVER workflow. This is not a speed-optimisation task. The reported problem is poor recognition on illustrated Japanese book/doujinshi covers: the existing Chrome Lens engine returns useful Latin text and some Japanese fragments, while PaddleOCR produces substitutions, irrelevant fragments, and fails to reconstruct the prominent Japanese title.

The priority is to determine whether the failure comes from the Rust/ONNX implementation, preprocessing, detector/postprocessing, crop geometry, recognizer, CTC decoding, Unicode/dictionary handling, or genuine PP-OCRv6 Medium limitations. Fix proven implementation defects first. Only then add measured cover-specific improvements.

Do not claim success because the app compiles or OCR returns some text. Require reproducible comparisons and accuracy metrics.

## 5. Evidence-based cover-specific improvements

Only after parity is established, add improvements justified by measured failures.

### 5.1 Multi-scale detection

Evaluate original-resolution full-cover detection plus bounded higher-resolution passes for small text and/or focused passes for promising text-dense/title regions.

- Bound scale factors, dimensions, memory and number of passes.
- Map every box back to original-image coordinates.
- Deduplicate cross-pass overlaps with documented geometry/text-aware rules.
- Measure detection recall, false positives, memory and latency impact.
- Use conditional passes where practical; do not multiply inference work without evidence.
- Do not imply upscaling can recreate detail absent from source pixels.

### 5.2 Vertical and rotated Japanese text

Verify the model's actual supported orientations and current pipeline behaviour. Where supported, handle vertical Japanese text and preserve reading orientation. Test controlled 90°/270° alternatives only when orientation is uncertain; do not rotate every crop blindly. Preserve original coordinates and prevent duplicate results. Do not claim general vertical-text support without representative tests.

### 5.3 Decorative and scattered typography

The supplied cover's main Japanese title is colourful, scattered and placed over illustration rather than arranged as one conventional line.

Investigate whether characters are missed, split, merged, clipped, warped or contaminated by background artwork. Evaluate crop padding, detector thresholds/box expansion, individual character/word crops, multi-scale recognition and orientation alternatives. If the recognizer fails on a correct crop, classify that as a model/domain limitation.

Do not promise that PP-OCRv6 Medium can recover every artistic title. Evaluate any additional model separately and only if its licensing, packaging, runtime and accuracy are justified. Do not replace Medium as a shortcut.

### 5.4 Recognition batching and resource reuse

Accuracy is primary. If batching is introduced, preserve crop identity and geometry, respect input constraints, bound memory and verify batched outputs against single-crop reference results. Do not let padding or batching change character proportions or decoding.

### 5.5 Multi-pass merge

Retain each candidate's raw text, score/confidence, original coordinates, orientation, pass identity and model identity. Merge only when geometric and textual evidence supports the same region. Avoid concatenating unrelated fragments into a false title. Keep plausible alternative readings when ambiguous. Do not discard a Japanese title candidate solely because its score is lower than a large Latin label. Do not assume detector order is reading order.

## 6. Structured OCR candidates and search preparation

OCR supplies evidence; it does not determine the final book identity.

Where compatible with the current architecture, represent candidates with:
- raw recognised text;
- separate normalised search text;
- confidence only when actually provided and meaningful;
- original-image polygon/bounding box;
- orientation where known;
- model/pass provenance;
- detection/recognition status.

Keep the shared `OcrTextSource` interface compatible and avoid unrelated architecture rewrites.

Do not blindly concatenate all fragments into one query. Add conservative query preparation that groups nearby text only when geometry/orientation supports it; prioritises plausible title/author/circle/identifier evidence; de-emphasises isolated tiny noise using measurable rules; preserves Japanese, punctuation and mixed Japanese/Latin; does not mistake `R-18`, volume numbers or generic labels for a title; and retains alternative queries when uncertain.

Never hardcode the supplied cover's title or words in production. If a title cannot be reconstructed, pass useful separate candidates downstream rather than inventing a joined title.

Preserve existing product identity rules: prefer exact doujin identifiers such as `RJ…`; use title with circle/author evidence; title-only matches are weaker; ownership and catalogue presence remain separate; never overwrite user-confirmed data automatically. Do not redesign DLsite, workbook matching, OpenCLIP, wishlist or collection persistence.
