# 3. Distinguish the Two Table-View Implementations

BookCoverMatcher has two separate situations in which a user can inspect spreadsheet data.

They must be treated as distinct UI entry points, even if they share rendering components or formatting utilities.

## 3.1 Catalogue → Table

This is the table function available from the Catalogue directory.

Its purpose is to provide a general tabular view of imported workbook data.

It should support the previously specified:

- Readable column and row presentation.
- Correct date formatting.
- Correct numeric and percentage formatting.
- Hyperlink representation.
- Cell selection and copying.
- Opening supported links.

## 3.2 Source Location → Source Worksheet Preview

This is the source-inspection view opened when a user needs to inspect the exact original spreadsheet location associated with a record or image.

The preview displays approximately 13 nearby source rows to provide context around the selected source cell or record.

Its purpose is different from Catalogue:

- It must show the original worksheet context.
- It must preserve the exact source-cell identity.
- It must make the relevant source location understandable.
- It must allow users to inspect nearby rows without losing the selected cell's context.

**The Source Location preview is currently missing several formatting and interaction capabilities already expected from the Catalogue table.**

Do not assume that fixing Catalogue automatically fixes Source Location. Trace both implementations separately.

# 4. Source Location Preview: Formatting and Data-Type Consistency

## 4.1 Current problems

The Source Location worksheet preview does not consistently use the latest formatting and interaction behavior.

Known problems include:

1. Excel dates are displayed as numeric serial values instead of readable dates.
2. Cell clicking and selection are not implemented consistently.
3. Cells containing hyperlinks are not visually distinguished using blue linked-cell styling.
4. The global maximum-two-decimal numeric display policy is not applied consistently.
5. Other formatting and interaction improvements already implemented or required in Catalogue may also be missing.

The listed problems are confirmed issues, not an exhaustive list.

Inspect the entire Source Location preview implementation to identify other missing formatting, metadata, and interaction behavior.

## 4.2 Correct Excel date formatting

Apply the same date-formatting logic used by the corrected Catalogue table.

Requirements:

- Recognize actual Excel date-formatted cells.
- Convert valid Excel date serials using the correct workbook date system.
- Respect supported date and time formats.
- Display readable date and time values.
- Preserve the original underlying source value and number-format metadata where supported.
- Do not interpret ordinary integers or decimal numbers as dates.
- Handle invalid and unsupported date values safely.

Do not implement a separate, inconsistent date conversion algorithm specifically for Source Location.

Use the shared formatting implementation where appropriate.

## 4.3 Global numeric display precision

Apply the existing global numeric display policy to Source Location.

Requirements:

- Display numeric measurements with no more than two decimal places.
- Avoid unnecessary trailing zeros unless a particular display format explicitly requires fixed precision.
- Preserve original raw values.
- Do not round before calculations or sorting.
- Do not round dates, times, identifiers, serial numbers, indexes, row numbers, or cell references.
- Respect percentage-specific number formats.
- Avoid double scaling percentage values.
- Preserve currency and other meaningful number formats.

The Source Location preview must not be excluded from the global numeric formatting policy simply because it displays original worksheet rows.

## 4.4 Preserve all supported source formatting

Inspect the formatting metadata available from the spreadsheet parser and the current canonical model.

Where supported, preserve and display relevant information such as:

- Date formats.
- Time formats.
- Percentage formats.
- Currency formats.
- Decimal precision.
- Hyperlinks.
- Text values.
- Empty cells.
- Invalid or unsupported values.

Do not fabricate formatting information that the source workbook does not provide.

Do not change the original workbook.

# 5. Source Location Preview: Cell Interaction

## 5.1 Cell click behavior

Implement cell selection and interaction in the Source Location worksheet preview.

When a user clicks a cell:

1. Identify the actual source cell.
2. Open the same central cell-value dialog required by the Catalogue table.
3. Display the selected cell's value.
4. Offer Copy.
5. Offer Open Link when the cell contains a valid supported hyperlink.
6. Offer Back.

The dialog should behave consistently across Catalogue and Source Location.

## 5.2 Exact source-cell identity

This is especially important for Source Location because its purpose is to inspect an exact source position.

The selected cell must be identified by stable source information, including:

- Workbook identity.
- Worksheet identity.
- Original source row.
- Original source column.

Do not use only the displayed row index or column position.

The preview displays approximately 13 nearby rows, so the visible row index must never be confused with the original worksheet row number.

Ensure that:

- Clicking a nearby row selects the correct original source row.
- Clicking a column selects the correct original source column.
- The displayed cell value corresponds to the selected source cell.
- Hyperlink metadata corresponds to the same cell.
- Sorting, filtering, scrolling, or preview-window positioning cannot cause a different cell to be selected accidentally.

## 5.3 Cell-value dialog

Use the same interaction specification as the Catalogue table.

The dialog must:

- Appear centrally.
- Display the complete selected cell value.
- Preserve meaningful spaces and line breaks.
- Handle long values without overflowing.
- Support scrolling when necessary.
- Provide vertically arranged actions.

Button order:

1. Copy.
2. Open Link, only when a valid supported hyperlink exists.
3. Back.

Clicking outside the dialog must dismiss it.

Clicking inside the dialog must not accidentally dismiss it.

System Back behavior should remain consistent with existing application conventions.

## 5.4 Copy behavior

Copy the displayed cell value, not its hyperlink destination.

Preserve the complete text, including meaningful spaces and line breaks.

Do not modify the original cell value.

Provide appropriate copy-success feedback.

## 5.5 Open Link behavior

When the selected source cell has a valid hyperlink:

- Display Open Link.
- Use the actual stored destination.
- Handle external website links using the appropriate platform mechanism.
- Handle supported internal workbook links using internal navigation.
- Validate unsupported or malformed destinations.
- Never fabricate a destination from the displayed value.

# 6. Linked-Cell Visual Representation

Ensure that both table-view implementations consistently identify linked cells.

This requirement applies to:

- Catalogue → Table.
- Source Location → Source Worksheet Preview.

Requirements:

1. Preserve hyperlink metadata from spreadsheet parsing.
2. Associate the hyperlink with the exact source cell.
3. Visually distinguish linked cells using blue text or the existing application link style.
4. Keep ordinary cell text visually distinct from actual linked cells.
5. Ensure the style remains readable in light and dark themes.
6. Preserve normal cell selection behavior.
7. Make linked cells interactive through the cell-value dialog.
8. Do not infer hyperlinks from arbitrary text.
9. Do not change the source workbook.

Use a shared link-style implementation where practical so both previews remain visually consistent.

# 9. Insights → Fields: Default Order Mapping Is Not Changeable

## 9.1 Current behavior

In Insights → Fields, the Default Order header mapping is still not changeable.

Unlike other mapped headers, it does not provide a button or equivalent interactive control that allows the user to select a different source column.

The previous requirement to allow manual reassignment has therefore not been fulfilled.

## 9.2 Expected behavior

Default Order must have a functional column-selection control comparable to other configurable headers in Fields.

The user must be able to:

1. View the currently selected Default Order source column.
2. Click a visible control to change the selected column.
3. Choose another available source column.
4. Confirm or apply the new mapping.
5. See the updated mapping in Fields.
6. Clear or unset the mapping where appropriate.
7. Reopen the workbook and retain the saved mapping.

The control must be visibly interactive and must not rely on an undocumented gesture or hidden action.

## 9.3 UI implementation requirements

1. Inspect how other headers in Fields expose their column-selection controls.
2. Use the same interaction pattern and visual conventions for Default Order.
3. Ensure the Default Order row has a visible button, dropdown, selector, or equivalent existing control.
4. The user must be able to activate the control using ordinary touch interaction.
5. Display available source columns with meaningful names.
6. Support arbitrary column headers and languages.
7. Clearly indicate the currently selected column.
8. Allow the user to change the selection more than once.
9. Provide an appropriate unset or clear option.
10. Provide validation and feedback.
11. Preserve existing layout and readability.

Do not merely add a label showing the current mapping. The user must have a working way to change it.

## 9.4 Automatic detection and manual override

Retain automatic detection of a likely Default Order column.

The expected behavior is:

- Automatically detect a likely column using the same general mechanism as other headers.
- Display the detected selection.
- Allow the user to manually override it.
- Preserve the manual selection until the user explicitly changes or resets it.
- Allow automatic detection to be applied again when the user chooses to reset to automatic behavior.

Do not hardcode `通し番号`, `Serial Number`, or any other header.

## 9.5 Persistence and Timeline integration

Persist the selected Default Order mapping using the existing workbook and mapping-profile architecture.

When the mapping changes:

- Update the canonical mapping state.
- Refresh dependent Timeline data.
- Use Default Order as the secondary ordering key for equal Published or Acquired dates.
- Preserve chronological date ordering as the primary key.
- Use deterministic fallbacks for missing or invalid ordering values.

Handle stale mappings safely if a source column is renamed, removed, or becomes unavailable.
