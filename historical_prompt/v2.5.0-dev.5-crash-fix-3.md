## 8. Stage D — Detector and recognizer session management

Implement reusable detector and recognizer sessions.

The inference layer must support the complete pipeline:

`RGBA image → detector preprocessing → detector inference → DB postprocessing → quadrilateral crops → recognition preprocessing → recognizer inference → CTC decoding → text ordering`

### Session requirements

- Load the detector model.
- Load the recognizer model.
- Validate model input and output metadata.
- Validate tensor dimensions.
- Validate data types.
- Validate dictionary compatibility.
- Reuse initialized sessions.
- Handle initialization errors.
- Handle inference errors.
- Avoid repeated model loading.
- Release resources safely.

The two sessions must have a clearly defined ownership and concurrency strategy.

Because the selected `ort` version requires mutable session access for `run`, do not introduce unsound shared references or concurrent mutable access.

For this phase, a simple serialized inference design is acceptable.

Do not optimize concurrency prematurely.

### Memory handling

Avoid unnecessary full-image copies.

Reuse intermediate buffers where practical.

Ensure:

- Tensor buffers remain alive for the duration of inference.
- Model output buffers are not accessed after their owners are released.
- Crop buffers have explicit ownership.
- Errors do not leak large allocations.
- Repeated inference does not cause unbounded memory growth.

- Failed crop.
- Invalid recognition input.
- Invalid recognizer output.
