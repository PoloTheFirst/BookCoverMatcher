## 19.5 Defect investigation and remediation

### CONFIRMED DEFECTS

**XLS-01 — a blank row silently truncates the catalogue** (prior report: `bug-register.md`, Medium)

* Observed: `layout_blank_rows.xlsx` → 8 comments, **3** records, no warning anywhere.
* Independently reproduced: **yes, twice** — at reader level (`CatalogueTruncationTest` drives
  `CatalogueReader.fromCells` over the same cell shape) and on the device (the same fixture, 3 records).
* Root cause: `CatalogueReader.fromCells` breaks on the first all-empty row after data starts
  (`if (records.isNotEmpty()) break`). The rule is intentional; the defect was that its consequence was
  never made data, so no consumer *could* report it.
* Files: `CatalogueTable.kt`, `HealthReportBuilder.kt`, `WorkbookBrowserPanels.kt`.
* Fix implemented: **yes** — count the rows below the gap that carry data in the table's own columns
  (`truncationBelow`, bounded by `maxRecords`), carry it on `CatalogueTable.truncation`, and show it in the
  Catalogue tab, the Table view and Health.
* Tests: `CatalogueTruncationTest` 6/6 + device verification (three surfaces, record count unchanged at 3).
* Remaining uncertainty: none for the reporting; the stop rule itself is unchanged by design.

**UI-01 — the default range excludes the title/image column** (prior report: `bug-register.md`, Low)

* Observed: fresh install, canonical layout, **Link & Find Top 5** → "No images found inside A1:B20…",
  zero results.
* Independently reproduced: **partially** — the shipped value was read directly (`Config.DEFAULT_RANGE`),
  `DefaultRangeTest` proves `A1:B20` excludes column `D`, and the device confirmed the new default. The
  full scan-and-find failure was **not** re-created this round (it needs a query embedding first).
* Root cause: the default (2 columns) is narrower than the documented layout (24 columns, covers in `D`),
  and `Prefs.range` returns that constant whenever the preference is unset; the message did not say what
  to change.
* Files: `Config.kt`, `MainViewModel.kt`.
* Fix implemented: **yes** — default `A1:Z5000` (a typed/stored range is never overwritten) and an
  actionable empty-result message.
* Tests: `DefaultRangeTest` 3/3 + fresh-install device check (`A1:Z5000`).
* Remaining uncertainty: **the reworded toast was not observed on the device.** Code-verified only.
