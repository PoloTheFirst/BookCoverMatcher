## A. Implementation summary

The work did two things: it reconciled every earlier `v2.4.0-dev*.md` requirement against the repository, and
it implemented the additional requirements in `v2.4.0-rc.2`.

New in this round:

1. **Default Order mapping** (`CatalogField.DEFAULT_ORDER`, `core/catalog/DefaultOrder.kt`). *Insights → Fields*
   gained an optional **Default order** row: any source column, any header, any language, changeable and
   clearable, saved with the mapping profile, with a preview that reports how many values are numbers, how many
   are text and how many are blank. The value is the workbook's own text (`0012` stays `0012`).
2. **Timeline tie-break.** The date remains the primary key. Records that share a Published or Acquired date are
   ordered by the Default Order value **ascending** — numerically (`2` before `10`), text after numbers, blanks
   last, then the verified source identity. Flipping newest/oldest no longer reverses the tie-break
   (`CollectionTimelineBuilder.entriesInOrder` / `ordered`). Without the mapping the previous fallback remains.
3. **Persisted view state** (`core/catalog/InsightsView.kt`, `data/InsightsViewStore.kt`,
   `files/mappings/insights-views.json`). Health, Analytics and Gallery each remember their own worksheet
   selection, and each timeline remembers its own year range, per workbook (SHA-256). Stale worksheet keys are
   reconciled; a workbook with no entry keeps the defaults.
4. **Cover First removed** as an ordering (`GallerySort.COVER`); the cover filters and the verified association
   are untouched.
5. **One numeric display rule** (`Formatting.decimal`, ≤ 2 decimals). Applied to the similarity score and to
   workbook cells whose number format declares decimals (`CellFormatKind.NUMBER`); `General`/integer cells and
   identifiers are never reformatted.
6. Carried over from the previous round and re-verified: the Gallery worksheet filter, the removal of the
   Imported Timeline mode, date/percentage rendering from `xl/styles.xml`, the 1900/1904 date system everywhere
   a serial is read, and version `2.4.0` / code `213`.

## C. Root causes and corrections

**1. Excel dates printed as serial numbers (Catalogue → Table).**
*Earlier behaviour:* `45292` / `43465` appeared in the table for cells Excel displays as dates.
*Cause:* `SheetCells.read` kept only the cell's text — the `s` (style) attribute and the workbook's
`xl/styles.xml` were never read — so the display layer had no way to know the cell was a date.
*Correction:* `WorkbookStyles` parses `numFmts`/`cellXfs`/`workbookPr@date1904` once per package;
`CellValue` keeps `styleIndex` and `numeric`; `CatalogueRecord.displayValues` holds the formatted text beside the
untouched `values`; `CellNumberFormat.display` renders `2024-01-01` / `2024-01-01 14:30`, honouring both epochs
and refusing serials `0` and `60`.
*Verification:* `CatalogueNumberFormatTest` (11), `CatalogueFormattingWorkbookTest` (4, a real OOXML package),
and the real `test_excel/doujin.xlsx` (`出版日付`/`購入日` display as dates, `価格（稅込）`/`ページ数` do not).

**2. Percentages shown as their stored fraction.**
*Cause:* same missing metadata; no percentage rendering existed.
*Correction:* `CellFormatKind.PERCENT` → `NumberFormats.percent` (×100 once, ≤ 2 decimals, trailing zeros
dropped, `-0%` normalised to `0%`); text cells are never scaled.
*Verification:* the percentage cases in `CatalogueNumberFormatTest` and the "scaled exactly once" test.

**3. The Imported timeline duplicated both other modes.**
*Correction:* the mode, its builder and its UI branch were removed; import timestamps stay as library metadata.
*Verification:* `CollectionTimelineTest`, `TimelineDateUiTest`, `WorkbookInsightsUiTest` assert the enum has
exactly `PUBLICATION` and `ACQUISITION`.

**4. Equal dates had no workbook-defined order.**
*Cause:* the timeline broke ties on the record id, so two records with the same date came out in worksheet order
and an alphabetical sort was impossible to ask for — but so was the workbook's own order.
*Correction:* `CatalogField.DEFAULT_ORDER` + `DefaultOrderValue` + `CollectionTimelineBuilder.entriesInOrder`:
date first, then Default Order ascending (numbers numerically, text after numbers, blanks last), then the record
identity; `ordered()` re-applies the same rule in either direction instead of reversing a sorted list.
*Verification:* `DefaultOrderTest` (10) and the real-workbook test that finds the fixture's `通し番号` and checks
a genuinely tied publication date.

**5. Worksheet selections and the year range were lost on restart.**
*Correction:* `InsightsView`/`InsightsViewCodec`/`InsightsViewStore` (one JSON file, temp+rename, tolerant
reads), restored on `open()` and written only from the actions that change them.
*Verification:* `InsightsViewPersistenceTest` (8).

**6. "Cover first" duplicated the cover filter as an ordering.**
*Correction:* the `COVER` entry and its chip were removed; `hasVerifiedCover` and the filters are untouched.

**7. Numbers could show more than two decimals.**
*Correction:* one rule (`Formatting.decimal`) for the similarity score and for decimal-formatted cells
(`CellFormatKind.NUMBER`); `General`/integer cells stay verbatim.

## G. Data integrity

* **Source workbooks unchanged:** the app opens a workbook read-only and never writes to it; the only writes in
  this round are the app's own JSON stores under `files/mappings/`. `test_excel/doujin.xlsx` was read through
  `ZipFile` only; its size and timestamp are untouched.
* **No VBA macros executed:** macros are never read or run (`isMinifyEnabled`/`vbaProject.bin` are not involved;
  the parser reads worksheet, styles, comments and VML parts only).
* **Unknown values stay distinguishable from zero:** a blank cell is `FieldState.MISSING` / an empty string, never
  `0`; a record with no date stays in the timeline's unknown bucket; a record with no Default Order sorts last and
  its value stays `null`.
* **No fabricated image associations:** only associations the comment scanner verified are used; unresolved and
  unreferenced media remain explicit, and the cover filters read that same state.
* **Raw numeric values preserved:** `CatalogueRecord.values` keeps the stored text; `displayValues` is a separate
  read-only layer used by the table and the cards. Filters, search, the canonical catalog, the CSV export and the
  source window read the stored text. The percentage and decimal renderings never write back.

## I. Outstanding issues

1. **Nothing was checked on a device or emulator.** The Gallery worksheet bar, the Default Order row, the
   persisted-restore path and the formatted table cells are covered by pure/state tests and by the build, but no
   screen was tapped through, and no screen width was measured. `app/src/androidTest` (OCR through Chaquopy and
   the live catalogue sources) needs hardware and was not run.
2. **No visual verification of the two-decimal rule outside the Catalogue.** The similarity score and the
   catalogue cells are covered by unit tests; the Health/Analytics/Timeline tiles show integer counts, which the
   rule does not change.
3. **The two-decimal rule is deliberately format-driven in the Catalogue.** A workbook that keeps prices in a
   `General` column (no decimals declared) still shows whatever Excel stored, because the app cannot tell a price
   from an identifier there. Fixing that would require a user-declared "measurement" field, which this release
   does not add.
4. **Currency symbols are not re-rendered.** The table shows the number; the workbook's own `¥`/`円` prefix stays in
   the workbook.
5. **The persisted year filter is kept even when the current data no longer has that year.** The timeline then
   shows an explicit empty result with *Clear filters* rather than silently dropping the range — a deliberate
   choice, but it can look empty right after a workbook change.
6. **Worksheet selections are not synchronised across devices** (the app is local-only) and are keyed by the
   workbook hash: a file re-saved by Excel has a new hash and therefore starts from *All worksheets*.
7. **Mapping profiles still store header names**, so a renamed column is reported as `HEADER_MISSING` rather than
   re-matched by position. That is intentional (a wrong guess is worse than an unmapped field) and is unchanged by
   this release.
8. **Recommended follow-up:** an on-device pass over the four Insights screens, a Compose UI test module if the
   project ever accepts that dependency, and an optional "treat this column as a measurement" mapping if users ask
   for the two-decimal rule on `General` columns.
