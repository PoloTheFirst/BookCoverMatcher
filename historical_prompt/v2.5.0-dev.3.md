# 5. Requirement 4 — Add a rubbish-bin icon to every IQDB card

## 5.1 Required UI

Every IQDB result card must display a rubbish-bin/trash icon in its top-right corner.

The icon must be consistently positioned across all IQDB cards.

Use the existing icon library and UI conventions. Prefer an appropriate Lucide icon such as `trash-2` if compatible with the project's current icon setup.

## 5.2 Interaction

The icon must be an actual interactive control.

When pressed:

- Remove the corresponding IQDB card from the currently displayed IQDB result list.
- Do not remove other IQDB cards.
- Do not remove SauceNAO results.
- Do not remove the underlying catalogue record.
- Do not remove a Wishlist bookmark.
- Do not delete cached source images unless the cache's normal eviction policy requires it.
- Do not modify the original provider's remote data.

This action should be a local dismissal of the result card, not a destructive deletion of a product.

If the application already has a suitable dismissal state, reuse it.

## 5.3 State behavior

- Dismissing one card must not reorder or unintentionally dismiss other cards.
- Dismissing a card must not cause stale asynchronous responses to reinsert it immediately.
- A new reverse-image search may show the result again unless the application already has a deliberate persisted dismissal mechanism.
- Do not introduce permanent dismissal persistence unless there is an existing suitable design.
- Preserve provider attribution for all remaining cards.

## 5.4 Accessibility

Provide:

- A suitable touch target.
- A descriptive accessibility label such as `Dismiss IQDB result`.
- A clear visual icon.
- No accidental activation when the user taps the rest of the card.

The trash icon must appear on every IQDB card, including cards in multi-result and paginated states.

It must not appear on SauceNAO cards unless the existing UI deliberately shares a component and the provider-specific behavior is handled correctly.
