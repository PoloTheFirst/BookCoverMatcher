## A. Implementation summary

| Group | What changed |
|---|---|
| **1. Source Location preview (`§3–§8`)** | The window model is no longer text-only: `SheetWindowCell(text, display, link)` carries each cell's **stored** text, the same cell **as the workbook displays it** (same `WorkbookStyles.display(styleIndex, text, numeric)` call the Catalogue table makes) and the workbook's **own hyperlink**. `SheetWindows.build(…, styles, links)` fills them; the controller reads `xl/styles.xml` and each worksheet's `<hyperlinks>`/`.rels` once per open (cached, cleared on open/rescan/close). Every cell of the preview is now a touch target that opens the **existing** `CellPeekDialog` (Copy / Open Link / Back), opened through `WorkbookCommentsUi.peekSourceCell(window, row, column)` → `SheetWindow.cellAt(row, column)`, i.e. by **worksheet row + column**, never by drawn position. Linked cells are accent-coloured and underlined; header cells are inspectable whether the header row is inside the window or carried above it. |
| **2. Default Order in Fields (`§9`)** | The field now has a first-class, visibly interactive control: its own card with bordered buttons **Change / Choose column**, **Clear** and **Use detected**, plus a line naming the detected column. Every other field row's muted "Change" word became the same bordered button. The mapping **in effect** is persisted per workbook (`WorkbookMapping` + `WorkbookMappingStore` → `files/mappings/workbook-mappings.json`) and restored on open, so a manual Default Order column survives navigation and a restart; *Detected* removes the entry. The picker's edit rule is one shared function (`withField`), and the picker no longer breaks on two columns sharing a header. |

No new dependency, no new architectural layer beyond one small core model + one store in the existing style,
and no change to the workbook file at any point.

## C. Root causes and corrections

**1. The Source Location preview printed the raw cell and could not be touched at all.**

* *Original behaviour:* a date-formatted cell read `45292`, a percentage `0.123456`, a currency cell its bare
  number; no cell was tappable, no linked cell was marked, and the preview had no Copy/Link at all.
* *Root cause:* the window model was text-only — `SheetWindowRow(row, values: List<String?>)` — and
  `SheetWindows.build` was never given the workbook's `WorkbookStyles` or its `<hyperlinks>`. The composable
  `SheetWindowView(window, chosen)` had no click handler and no controller reference, so there was nothing to
  open a dialog with. Catalogue's formatting/dialog work lived entirely on the `CatalogueRecord` path and
  simply never reached this second, independent preview.
* *Correction:* `SheetWindowCell(text, display, link)`; `SheetWindows.build(…, styles, links)`; the controller
  caches `styles` and per-sheet `links` (cleared on open/rescan/close with `clearCellMetadata()`);
  `SheetWindow.cellAt(row, column)` resolves a cell by source identity; `WorkbookCommentsUi.peekSourceCell`
  reuses the existing `CellPeekUi`/`CellPeekDialog`; `WindowCell` is tappable, accent-coloured and underlined
  when linked.
* *Verification:* `SourceWindowFormattingTest` (14) on a real package with its own `styles.xml` and both link
  kinds — dates, percentages, currency/`General` cells, link ownership, blank cells, row/column identity, a
  carried header, and the dialog's value/label/link/silence. Plus a real-workbook test comparing both views
  column by column.

**2. The Default Order mapping could not actually be changed.**

* *Original behaviour:* *Insights → Fields* showed a "Default order" line whose value preview was read-only;
  the one column the timeline depends on looked locked, and nothing about the choice survived a restart.
* *Root cause (verified in the code, not assumed):* the field *was* in the generic list
  (`items(CatalogField.ordered)`) and its row *was* clickable, but (a) its only affordance was a plain muted
  `Text("Change")` — no border, no button styling — so nothing looked interactive; (b) a second, read-only
  `DefaultOrderNote` card for the *same* field sat directly below it, saying "change it here or in a profile"
  without any control, which made the field's own panel the one that could not be edited; and (c) the applied
  mapping was session state only, so even a successful change was lost when the workbook was reopened, which
  the prompt's §9.2.7 requires.
* *Correction:* the read-only note became `DefaultOrderCard` with bordered `MappingButton`s (**Change** /
  **Choose column**, **Clear**, **Use detected**) and the same "read from …" statistics; the generic list no
  longer duplicates the row; every `FieldRow` now shows the same bordered button; `Map.withField` is the one
  edit rule (`mapField` uses it); `HeaderPickerDialog` keys its rows by position so duplicate headers cannot
  break it; and `WorkbookMapping`/`WorkbookMappingStore` persist the mapping in effect per workbook, restored
  by `restoredMapping` during `open()`.
* *Verification:* `MappingPersistenceTest` (11) — codec tolerance, the per-workbook store, a manual mapping
  round-trip including the Default Order column, a live profile, a deleted profile, *Detected* clearing the
  entry, the `withField` edit rule, and `detectedHeader`/`defaultOrderIsDetected` including the "nothing
  detectable" case.

**3. Two columns with the same header could not be chosen (found during the audit).**

* *Original behaviour:* `HeaderPickerDialog` used `items(headers, key = { it })`; a worksheet whose header row
  repeats a name would have made the picker throw on a duplicate `LazyColumn` key at the moment a user opened
  it — i.e. exactly the "control does not work" symptom.
* *Correction:* `itemsIndexed`, so both entries stay choosable and the resolver keeps reporting
  `HEADER_AMBIGUOUS`. *Verification:* code-level (a duplicate-key crash cannot be exercised without a Compose
  UI-test dependency); the ambiguity reporting itself is covered by `ColumnMappingStoreTest`.

## D. Catalogue versus Source Location comparison

Same workbook, same cell, both views (`SourceWindowFormattingTest` asserts this for **every** column of a
record, and `SampleWorkbookColumnsTest` repeats it on the real `test_excel/doujin.xlsx`):

| Behaviour | Catalogue → Table | Source Location → Preview | Same? |
|---|---|---|---|
| Date formatting | `CellNumberFormat.display` (1900/1904, serials 0/60 refused) | identical call | **Yes** |
| Time / date-time | `14:30`, `2024-01-01 14:30` | identical | **Yes** |
| Percentage | `12.35%`, scaled once, ≤2 decimals | identical | **Yes** |
| Currency | number only, `Formatting.decimal` when the format declares decimals (`1200`) | identical | **Yes** |
| Ordinary / `General` numbers | shown exactly as stored (`42`) | identical | **Yes** |
| Hyperlink styling | `Palette.Accent` + `TextDecoration.Underline` | same tokens | **Yes** |
| Linked-cell metadata | `CatalogueRecord.links` by source column | `SheetWindowCell.link` by source row+column | **Yes** (same `SheetLinks` map) |
| Cell selection | tap a cell (row number still opens the row) | tap a cell (header cells included) | **Yes** |
| Copying | `CellPeekUi.value` = displayed text | identical | **Yes** |
| Opening links | `openPeekedLink` (browser / source overlay) | identical | **Yes** |
| Source-cell identity | sheet + record row + field column | sheet + window row + window column | **Yes** (same `CellPeekUi`) |

Differences that remain, and why they are intentional:

* **Layout and context.** The table is a lazy list of every record with a frozen row-number column and one
  shared horizontal scroll; the preview is a fixed ~13-row window of the worksheet with Excel's column letters,
  the verified row/cell highlighted and its catalogue header attached. The preview also reports
  `n of m column(s)` when a sheet exceeds the 96-column bound; the table draws every column it keeps. Neither
  is a formatting difference — the value in a cell is spelled the same in both.
* **What clicking a row number does.** In the table it opens the whole row in the source view; in the preview a
  row number is only a label (the row is already on screen), and the *cells* are the targets.
* **Stored vs displayed text.** Both views keep the stored text for filters/search/export and show the
  displayed text; a filter chip is chosen from what is shown, so two source values that display identically are
  one chip. This is shared behaviour, not a divergence.
* **Not drawn twice.** In the preview the header row is either one of the drawn rows (when it is inside the
  window) or a separate band above them — never both.

## E. Default Order mapping verification

* **Automatic detection.** `ColumnMappings.detectedProfile(table)` still runs on the workbook's own headers
  through the same alias table as every other field (no `通し番号`, `Serial Number` or any other literal in
  `src/main`). `WorkbookCommentsUi.detectedHeader(CatalogField.DEFAULT_ORDER)` exposes the result to the
  screen, and `defaultOrderIsDetected` says whether the current draft already matches it.
* **The control.** In *Insights → Fields* the Default order card shows the current column (or "Not mapped"),
  the value statistics, then **Change** (labelled **Choose column** when nothing is mapped) → the shared
  `HeaderPickerDialog` listing the worksheet's own headers plus *Not mapped*, **Clear** → `mapField(field, null)`,
  and **Use detected** (only when there is a detected column that differs) → `mapField(field, detected)`. Every
  other field row shows the same bordered **Change** button.
* **Applying.** Picking a column rewrites only that key of `mappingDraft` (`Map.withField`), re-previews the
  worksheet through the same builder the reports use, and updates the card immediately; **Apply mapping**
  commits the draft to `appliedMapping`/`activeProfile` and calls `refreshInsights`, which rebuilds Health,
  Analytics, Gallery and both timelines.
* **Persistence.** `persistableMapping()` (profile name + the columns in effect) is written by
  `WorkbookMappingStore` on Apply, Save profile, picking a profile, deleting the profile in effect, and on
  *Detected* it is **deleted**; `open()` loads it and `restoredMapping` re-applies it (as the saved profile when
  it still exists, otherwise as a manual mapping). Unapplied drafts are never stored.
* **Clearing / reverting.** *Clear* unmaps the column (records then fall back to their worksheet row);
  **Use detected** puts detection's column back; **Detected** in the profile chips drops the whole manual
  mapping and its stored entry.
* **Timeline integration.** `CollectionTimelineBuilder.entriesInOrder` keeps the date as the primary key and
  uses Default order only as the secondary key (`DefaultOrderValue`: numbers numerically, text after numbers,
  blanks last), with the verified source row as the final deterministic tie-break, in both directions.
* **Stale mappings.** A stored header the worksheet no longer has (renamed/removed column) resolves to
  `HEADER_MISSING` and leaves the field unmapped for that sheet rather than matching another column.

## I. Outstanding issues

1. **No device or emulator pass.** The preview's tappable cells, the blue underline, the dialog's outside-tap
   dismissal, the clipboard write, the browser intent, the in-workbook jump and the new Fields buttons were
   compiled and their state/model is unit-tested, but not tapped through. The project still has no Compose
   UI-test dependency; `app/src/androidTest` (OCR + live catalogue) needs hardware and was not run.
2. **The clipboard and intent calls themselves are untested** — they need an Android runtime. What they read
   (`CellPeekUi.value`, `CellLink`) is fully tested, including that a source cell copies its *displayed* value.
3. **Only `Sheet!Cell` internal links are followed.** A defined name, a `file://` path or a scheme with no
   handler keeps its destination in the dialog but offers no **Open Link** (deliberate, documented).
4. **Bounds inherited from earlier rounds:** the preview draws at most 96 columns (and says how many it left
   out); a hyperlink whose `ref` covers more than 1024 cells attaches to that range's first cell rather than
   being expanded; the two-decimal rule still needs a number format that declares decimals.
5. **The stored mapping is the applied one.** An unapplied draft is not remembered (by design), and the store is
   scoped per workbook — two workbooks of the same collection each keep their own, which is the intent.
6. **The Images/Catalogue worksheet picker is still session state** (unlike the three Insights scopes); the
   stale claim that Gallery/Health/Analytics were not persisted was removed from the changelog.
7. **Recommended follow-ups:** an on-device pass of both previews and the Fields screen; an optional Compose
   UI-test module so a tap can be asserted; and, if a `General`-formatted column ever needs the two-decimal
   rule, a user-declared "measurement" field rather than guessing from the value.
