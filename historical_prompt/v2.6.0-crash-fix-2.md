## 4. Defect B — Pacman contribution graph remains static

### 4.1 Reproduce the current behaviour

The previous Crash-fix-1 report stated:

- Source SVG contains 54 `<animate fill>` and 6 `<animateTransform>` elements.
- Declared duration is `29400ms`.
- Source frame rate is 5 fps.
- `SmilAnimation` samples the SVG document timeline and rewrites animated attributes.
- `AnimatedSvgPicture` swaps rendered frames.
- A pixel comparison 1.4 seconds apart detected changes.
- Expanded page performance was approximately 4.3 fps.
- Collapsed page produced zero frames in 10 seconds.

However, the user still observes a static Pacman contribution graph.

Do not dismiss this report or repeat the same test without investigating the discrepancy.

Test the actual current APK on a running emulator/device, with the Author page visible for long enough to observe multiple animation cycles.

Record:

- Device/emulator and Android version.
- APK build and version.
- Whether the Author page is expanded and visible.
- Whether the animation clock advances.
- Whether the generated SVG frames differ.
- Whether the rendered screen pixels differ.
- Whether Pacman or the contribution graph visibly changes.
- Whether animation stops when the page is hidden.
- Whether it resumes when the page becomes visible again.

A changing internal frame counter is not proof of visible animation. A screenshot of a single frame is not proof of animation.

### 4.2 Investigate the entire animation pipeline

Trace:

`Original animated SVG → SVG parser → SMIL timeline sampling → animated attribute evaluation → static SVG frame generation → AndroidSVG rendering → frame scheduling → Compose invalidation → visible screen`

Inspect the actual `SmilAnimation` and `AnimatedSvgPicture` implementations.

Investigate:

#### SMIL timeline correctness

- Whether the document's time origin is correct.
- Whether elapsed time is monotonic.
- Whether the full `29400ms` timeline is sampled correctly.
- Whether `<animate>` and `<animateTransform>` are both evaluated.
- Whether `begin`, `dur`, `repeatCount`, `repeatDur`, `fill`, `values`, `keyTimes`, `keySplines`, `from`, `to`, and `by` are handled as required by the actual source.
- Whether indefinite or repeated animations behave correctly.
- Whether multiple simultaneous animations are evaluated at the same timestamp.
- Whether the animation resets correctly at the end of a cycle.
- Whether nested SVG elements and inherited attributes retain correct state.

Do not assume every SMIL feature needs implementation. Implement and test the features actually used by the Pacman source, and document unsupported features.

#### Frame generation

- Whether each sampled timestamp produces genuinely different SVG content.
- Whether animated values are applied to the correct element.
- Whether generated frames preserve namespaces, definitions, IDs, styles, references, and transforms.
- Whether the frame-generation process accidentally freezes an initial value.
- Whether the renderer or cache returns the first frame repeatedly.
- Whether generated SVG strings or bitmaps are cached with an incorrect key.
- Whether the timestamp is part of the cache key where necessary.

#### Frame scheduling and Compose

- Whether frame scheduling continues while the Author page is visible.
- Whether the scheduling coroutine is cancelled prematurely.
- Whether lifecycle state or visibility incorrectly marks the page as inactive.
- Whether Compose receives observable state updates for every new frame.
- Whether recomposition actually updates the rendered image.
- Whether `remember` or another cache retains an obsolete image.
- Whether frame state is mutated outside Compose's observable state.
- Whether the image component is accidentally using only the first frame.
- Whether a timer or frame loop is blocked or suspended.
- Whether multiple loops start during recomposition.

#### Visibility and lifecycle

- Animation should play while the graph is visible.
- Animation should stop or pause when the Author page is collapsed or not visible.
- Animation should resume when the page becomes visible again.
- Full-screen navigation and returning to the Author page must not leave the animation permanently stopped.
- Repeated expand/collapse must not create duplicate animation jobs.
- App background/foreground transitions must be handled safely.
