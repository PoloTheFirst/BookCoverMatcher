## 1 · What this task did

The previous task ended with the Rust pipeline decoding real text on the host. This task put that
pipeline inside the Android app:

* JNI entry points in the crate (`src/jni.rs`, `src/wire.rs`, `src/registry.rs`) — no pointers cross
  the boundary, no panic can escape, allocations are bounded.
* A Kotlin adapter (`com.bookcovermatcher.ocr`) implementing the **existing** `OcrTextSource`, with a
  pure-Kotlin protocol parser, a SHA-256-pinned model store, and an engine selector.
* Both shipped ABIs cross-compiled and packaged through Gradle's `jniLibs`; the APK was inspected.
* Models installed on a device and verified there; real inference executed and compared with Python.
* A debug-only engine switch, so the native engine can be exercised without exposing it to users.
* Documentation: `native/ocr/README.md`, new `NATIVE_OCR_ANDROID.md`, this report.

## 2 · Architecture

### 2.1 JNI surface (stable, minimal)

| Kotlin (`NativeOcrLib`) | Rust (`src/jni.rs`) | Contract |
|---|---|---|
| `version()` | `…_version` | crate version string |
| `create(det, rec, dict, runtime)` | `…_create` | `> 0` handle, or throws with a sentence |
| `describe(handle)` | `…_describe` | `BC-OCR-INFO 1` payload |
| `recognise(handle, argb, w, h)` | `…_recognise` | `BC-OCR-RESULT 1` payload |
| `destroy(handle)` | `…_destroy` | idempotent |

* Kotlin holds an `i64`, never a pointer. `src/registry.rs` maps ids to `Arc<EngineHandle>`; ids are
  never reused; `destroy` is idempotent; an unknown id throws. An in-flight call keeps the engine
  alive while `destroy` runs, so `destroy` cannot free a session mid-inference.
* Every entry point is wrapped in `catch_unwind`: a Rust panic becomes `IllegalStateException`
  instead of unwinding into ART.
* Dimension validation (`1…8192` per side, ≤ 16.7 Mpx, buffer length must equal `w*h`) happens before
  any allocation.
* One `Mutex<OcrEngine>` per handle, matching the crate's `&mut self` contract; ONNX Runtime forbids
  concurrent `run` on a session, so requests queue rather than race.

### 2.2 Kotlin adapter

`RustOcrTextSource` implements `OcrTextSource` unchanged. It decodes the capture with the app's
existing `AndroidImageCodec.decodePhoto` (EXIF-aware, same 1280 px long edge as the Python path) and
passes `IntArray` ARGB pixels; Rust converts to RGBA. Results map to the existing `OcrText`:

| `OcrText` field | Value from the native engine |
|---|---|
| `text` | lines joined with `\n` |
| `blockHeights` | each line's quad height ÷ image height (the same normalised measure the query extractor already uses) |
| `detectedLanguage` | `null` — PP-OCRv6 is not language-conditioned; nothing is guessed |
| `translatedText` | `null` — there is no translation step |
| `wordCount` / `blockCount` | whitespace-split tokens / recognised lines |
| `libraryVersion` | `bc_ocr (PP-OCRv6 medium) 0.1.0 · ppocrv6-medium` |

`availability()` is cheap by design: it checks the library, model presence and the recorded
verification, and does **not** open the 139 MB of sessions (that happens lazily on the first
`recognise`, ~2 s measured).

### 2.3 Engine selection

`SwitchingOcrTextSource` reads `OnlineSearchPrefs.ocrEngine` (`"python"` default, `"rust"`) on every
call and closes the previous delegate when the selection changes. The UI switch is rendered only when
`BuildConfig.DEBUG`. Unknown stored values fall back to Python. There is **no automatic fallback** in
either direction: a selected-but-missing engine reports its own error.

## 4 · Model distribution

| Aspect | Decision |
|---|---|
| Approach | **Installed from a developer-supplied directory**, never bundled (139 MB would triple the APK) and never downloaded (the app must not pull that much on its own) |
| Provenance | The exact artifacts verified in `v2.5.0-dev.5-ag.md`: `PP-OCRv6_medium_{det,rec}_onnx` at revisions `6132380…` / `50c7eac…`, dictionary blob `270082aa…` |
| Integrity | SHA-256 pinned in `PpocrModels.PINNED_SHA256`; all three must match before any file is promoted; `.part` files; atomic rename; a `verified.txt` marker records name + hash + length so a 139 MB re-hash is not paid on every launch |
| Storage | app-private `files/ocr/ppocrv6/{det.onnx, rec.onnx, ppocrv6_dict.txt}` |
| Offline | fully offline: the engine needs no network at all (verified by running with the models installed and no download path) |
| Failure handling | missing → `OCR_MODELS_MISSING` with a sentence; wrong hash → the same category with the offending file named; never a silent substitution |

`tools/push-ocr-models.ps1` hash-checks the **local** files before pushing, then installs on-device by
staging into `/data/local/tmp`, making it readable, and copying with `run-as` so the files carry the
app's UID.

## 6 · Defects found during integration (and how each was fixed)

Integration found six real problems. None was papered over; each is now covered by a test or a
documented rule.

1. **JNI symbol mismatch.** The `external fun`s live on `NativeOcrLib`, but Rust exported
   `Java_…_NativeOcr_*`; every call failed with `UnsatisfiedLinkError`. Fixed by exporting the symbols
   for the class that declares them, and the device test now calls all five entry points.
2. **`dlopen` by absolute path is refused on Android.** Passing
   `/data/app/…/lib/x86_64/libonnxruntime.so` failed inside the app's linker namespace. Fixed by
   resolving the runtime **by soname** (after `System.loadLibrary("onnxruntime")`), which reuses the
   mapping Maven's dependency already created — and keeps exactly one runtime in the process.
3. **The app cannot read a shell-owned external directory.** `adb push`ing models into
   `/sdcard/Android/data/<pkg>/files` produced `exists=false` from the app, i.e. "models missing".
   Fixed by installing into app-internal storage via `run-as`.
4. **Windows `type` truncated binary models to 4 bytes.** `type` is a *text* command and stops at the
   first `0x1A`; the install stream was silently short. Fixed by staging with `adb push` +
   `chmod` + `run-as cp`, and the SHA-256 check would have caught it regardless.
5. **AGP's reinstall wipes installed models.** `connectedDebugAndroidTest` uninstalls first, so
   model-dependent tests skip when it runs after `push-ocr-models.ps1`. Documented: run the Gradle
   suite first, or run `am instrument` (no reinstall), as `NATIVE_OCR_ANDROID.md` §9 shows.
6. **A skipped test printed as "OK".** `am instrument` reports assumption-skipped tests inside
   `OK (n tests)`; only the XML/`-r` status codes distinguish them. The device test now **logs why**
   it skipped (`models: absent …`), and this report uses the XML counts (0 skipped) rather than the
   summary line.
