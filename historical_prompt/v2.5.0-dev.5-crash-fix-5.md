- CHW layout.

- Height: 48.

- Right padding.
- Normalization: `(v / 255 - 0.5) / 0.5`.
- Tensor shape: `[1, 3, 48, 320]`.

## 6. The unresolved dictionary mismatch

The recognizer outputs:

`18,710 classes`

The dictionary extracted from the model's own `inference.yml` currently contains:

- 18,705 entries according to configuration inspection.
- 18,704 entries in the extracted dictionary file.

The current decoder therefore rejects the output with an error similar to:

`recogniser outputs 18710 classes but the dictionary maps 18706 (18704 characters + blank + space); refusing to decode`

The exact counts and indexing convention must be independently rechecked.

A separate dictionary containing 19,053 entries was previously downloaded from a manga fine-tune. It was rejected because it belongs to a different model configuration.

Do not reuse it merely because its size appears closer to the expected count.

### Non-negotiable safety rules

Never:

- Truncate recognizer logits.
- Pad the dictionary with guessed characters.
- Ignore unexplained output classes.
- Substitute a dictionary from another model.
- Assume the final few classes are special tokens without evidence.
- Use Unicode sorting to reconstruct the original vocabulary.
- Deduplicate characters if doing so changes the original indices.
- Claim that text recognition works merely because ONNX inference succeeds.

The decoder must continue refusing unsafe decoding until the exact mapping is established.

- Export scripts.
- Vocabulary-generation code.
- Character encoding and normalization.
- Special-token handling.

1. Missing vocabulary entries.
