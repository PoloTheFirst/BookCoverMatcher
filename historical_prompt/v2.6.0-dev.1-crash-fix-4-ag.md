## 2 · The exact user-visible failure

> "The connection to OneDrive is failed, so nothing was saved. Try again when you are back online."

**Executed** a tree-wide search for every variant. Exactly one string matches, in
`core/remote/RemoteFailure.kt`:

```
RemoteFailure.Unstable -> "The connection to OneDrive failed, so nothing was saved. Try again when you are back online."
```

The user's "is failed" is a paraphrase of "failed". Two renderings exist for it:

| Call site | Wording |
|---|---|
| `RemoteFailure.message()` — used when the failure happens **before** a download starts (panel open, listing, token) | the sentence the user quoted |
| `RemoteNotices.forDownload(Unstable, name)` — used **during** a download | "The connection was lost while downloading *name*. Nothing was saved. Retry when you are back online." |

Since the user's quote contains no file name, their failure most likely occurred **before** the transfer — at
panel open, listing, or token acquisition — but that is an inference from the wording, stated as such. Nothing
else in the app can produce that sentence: `Offline` says "No internet connection…", `AuthExpired` says "Your
OneDrive sign-in expired…", `NotFound` says "This workbook is no longer in OneDrive…".

## 4 · Root cause

**One bucket for everything that is not a network error.** `AuthFailure.UNKNOWN` mapped to
`RemoteFailure.Unstable`, and `failureOf()` put *every* MSAL exception except `MsalUiRequiredException` and
`IOException` into `UNKNOWN`. `Unstable` is rendered with the sentence the user quoted. A cancelled page, a
declined consent, an unregistered redirect, a rejected client, an HTML error page parsed as JSON, a 3xx with no
`Location`, and any unexpected exception during a transfer therefore all became "the connection to OneDrive
failed … try again when you are back online".

Two supporting defects, both proven here:

* **A failed sign-in was invisible.** `signIn()` flattened every failure to `AuthState.SignedOut`, which the
  ViewModel treats as "the user cancelled" (`failureOrNull()` is null), so the reason was swallowed.
* **No connectivity preflight on interactive sign-in.** `openOneDriveBrowser` preflights; `signInToOneDrive` did
  not (§5.2).

`MsalException` or a Graph response the app could not use. Distinguishing them needs one run on the user's
