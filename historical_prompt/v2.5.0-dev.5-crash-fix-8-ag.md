Two facts decided the work:

1. **crash-fix-7 already fixed the routing half.** `OcrEngineChoice`, the always-visible selector,
   per-request engine capture, `OcrUi.Done/NoText.engine` and `OnlineSearchLog.ocrEngine*` are in
   `21dc0af`, with 13 JVM tests and 8 device routing tests. Re-reading `OnlineSearchController.readCover`
   confirmed the engine is captured before the coroutine starts and dispatch goes through
   `SwitchingOcrTextSource` → `RustOcrTextSource` / `ChromeLensPyBridge`, with no fallback.
2. **The distribution half was missing entirely.** `PpocrModels` only resolved models from a directory a
   developer prepared with `tools/push-ocr-models.ps1`. No assets were packaged, nothing was fetched at
   build time, and nothing extracted anything at first launch. On a clean installation the selector
   could therefore only ever answer *PaddleOCR unavailable — models not installed*.

## 2 · Root cause of the remaining problem

> The engine **selection** was wired; the engine **deployment** was not.

Not a routing bug, not a stale label, not a preference bug. A user who installed the APK had no path to
a working PaddleOCR: the code existed, the models did not, and the only documented way to install them
was ADB + a PowerShell script + a debuggable build. Every acceptance criterion that started with
"install a distributable APK on a clean device" was unreachable.

## 6 · Final execution-routing architecture

```text
Online panel → READ THE COVER → OnlineSearchController.readCover
    engine = OcrEngineChoice.fromStored(prefs.ocrEngine)      (captured before the coroutine starts)
        ↓
SwitchingOcrTextSource(engine)                                 (closes the previous engine on a switch)
    ├── Chrome Lens  → ChromeLensPyBridge → Chaquopy → lens_bridge.py → chrome-lens-py 3.8.2
    └── PaddleOCR    → RustOcrTextSource
                          ├── PpocrModels.ensureInstalled(assets::open)   ← NEW
                          │      files/ocr/ppocrv6/*.onnx + dict, SHA-256 verified
                          ├── AndroidImageCodec.decodePhoto → PixelImage
                          └── NativeOcr → libbc_ocr.so → OcrEngine → ONNX Runtime 1.20.0
        ↓
OcrText (same contract for both engines)
        ↓
Existing online-search workflow (Open Library / Google Books / DLsite)
```

Availability, selection and execution are three separate states: the chips show the **selection**, the
line under them shows **availability** (`Ready(…version)` or `Unavailable(failure, reason)`), and the
result line plus `OnlineSearchLog` record the engine that **actually ran** (`id=rust|python`).

## 7 · UI behaviour and preference migration

* Selector unchanged from crash-fix-7: `Chrome Lens` (default) / `PaddleOCR (PP-OCRv6 Medium)`, always
  visible, persisted in `OnlineSearchPrefs.ocrEngine`.
* Legacy `"python"` still means Chrome Lens; `"rust"`, `paddle`, `paddleocr`, `ppocr` mean PaddleOCR; an
  unknown value resolves to the default and is **not** rewritten on read.
* New here: availability no longer depends on a developer push. `availability()` runs the extraction on
  the controller's IO dispatcher and then reports `Ready(bc_ocr (PP-OCRv6 medium) 0.1.0 · ppocrv6-medium)`.
  If extraction or verification fails it reports `Unavailable(OCR_MODELS_MISSING, reason)`; the stored
  selection is preserved and nothing falls back to Chrome Lens.
* No fallback in either direction, unchanged.

## 12 · Remaining limitations

1. **No physical-device run.** Everything above is emulator x86_64. ARM latency, memory and thermal
   behaviour are unverified; `OcrEngineRoutingTest` and `NativeOcrDeviceTest` have not been run on a
   phone. This is the one level still open.
2. **First-use extraction costs time.** ~2.2 s for 132 MiB on the emulator; a cold phone will be slower.
   It happens inside the first OCR request, is retryable, and does not block other features.
3. **Universal APK only.** No ABI splits, no AAB/asset-pack delivery. A universal APK is ~316 MiB;
   Google Play's base-module limit is 200 MB, so Play distribution would need an install-time asset pack
   (still zero user action). The project ships sideloaded APKs, where no such limit applies.
4. **No language detection or translation** on the native path; no per-language accuracy claim (no
   reference transcriptions exist for real scans).
5. **Inference cannot be interrupted**; cancellation discards the result.
6. **Chrome Lens / Python untouched**; retirement remains out of scope.
7. **`tools/push-ocr-models.ps1` still exists** for builds made with `-x preparePaddleOcrAssets`, but no
   ordinary build needs it.
