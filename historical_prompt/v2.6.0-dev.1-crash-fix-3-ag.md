## 4 · The MSAL redirect failure: what actually happens

### 4.1 The flow, traced in the code

**Inspected**: `OneDriveUi.kt`, `MainViewModel.kt` (`signIn` at :851 passes the host `Activity`),
`MsalOneDriveAuth.kt` (`AcquireTokenParameters.startAuthorizationFromActivity(activity)` with
`Files.Read`/`User.Read`), `core/remote/MsalConfig.kt`, `app/build.gradle.kts`
(`azureRedirectForManifest` → `redirectParts` → `manifestPlaceholders`), `AndroidManifest.xml`
(`com.microsoft.identity.client.BrowserTabActivity` with `${azureRedirectScheme}`, `${azureRedirectHost}`,
`${azureRedirectPath}`), and the generated `res/raw/msal_config_default.json`.

Nothing in that chain is missing or wrong: MSAL is initialised from the packaged configuration, the interactive
call is started from a live Activity, the callback is a `CompletableDeferred` settled by MSAL's
`AuthenticationCallback` (success/error/cancel), and the manifest declares the MSAL redirect activity.
The failure is one level lower — in **intent resolution**, i.e. whether Android can find that activity for the
URI the browser receives.

### 4.2 Reproduction, on the device, without a Microsoft account

A custom-scheme redirect can be tested exactly the way a browser resolves it, with `am start` and the real
`msauth://` URI. **Executed** against the APK built from the checkpoint commit — at that point `dumpsys package`
showed the filter literal as `/` + the **percent-encoded** hash (`%2B`, `%3D`), i.e. byte-for-byte what the Azure
portal prints. The three probes (the concrete hash is deliberately elided here; it is the one configured in the
git-ignored `.env` and readable from the installed package):

| Probe | Intent data | Result |
|---|---|---|
| 1 | `msauth://com.bookcovermatcher/<hash-with-%2B-and-%3D>` — **what Azure/browsers send** | `Error: Activity not started, unable to resolve Intent` |
| 2 | `msauth://com.bookcovermatcher/<hash-with-+‐and-=>` — decoded base64 | `Error: Activity not started, unable to resolve Intent` |
| 3 | the same hash **double**-encoded (`%252B`, `%253D`) | **`Starting: Intent { … }` → resolves** |

Probe 3 is the discriminator: a URI only resolves when its **decoded** path equals the filter's literal. That is
precisely the blank page the user reported — the browser had no handler for the redirect, so it stayed on a
blank document and the app never resumed, even though Microsoft had already returned a success response.

### 4.3 Root cause (established, not assumed)

**The intent filter declared the signature hash in its percent-encoded form.** Android matches
`IntentFilter`'s literal `android:path` against `Uri.getPath()`, which is the *decoded* path, so
`…%2B…%3D` in the manifest can never equal the decoded `…+…=`. The Azure portal prints the redirect
percent-encoded, and the build copied it verbatim into the placeholder.

Contributing detail: the same trap cannot be avoided by "just decoding with `URLDecoder`" — that decodes
`application/x-www-form-urlencoded`, where `+` means a space, and a base64 hash contains real `+` characters.
The decoder had to handle `%XX` only. This is pinned by a test.

## 5 · The fix (smallest change that removes the cause)

| File | Change |
|---|---|
| `app/build.gradle.kts` | `redirectParts()` now runs the path through a new `decodeManifestPath()` (percent-escapes → UTF-8, `+` untouched) before it becomes `${azureRedirectPath}`; a build-time guard throws if escapes survive decoding. `redirect_uri` is **not** rewritten. Adds `import java.io.ByteArrayOutputStream` (the `java` name is shadowed by Gradle's `java` extension inside a `.kts`). |
| `core/remote/MsalRedirectPath.kt` **(new)** | Pure object holding the rule: `signatureHash()`, `intentFilterPath()` (decoded, leading slash), `isDerivedForm()` for `msal<client-id>://auth`, and `decodePercentEscapes()` with the `+`-is-not-a-space comment. |
| `core/remote/MsalConfig.kt` | `redirectProblem()` now uses `MsalRedirectPath.signatureHash()` and additionally rejects a redirect whose hash decodes to nothing. Acceptance of both legal redirect shapes is unchanged. |
| `core/remote/MsalRedirectPathTest.kt` **(new)** | 9 tests (§9). |
| `AndroidManifest.xml` | **Unchanged** — it already used the placeholders; only the value they resolve to changed. |
| `ARCHITECTURE.md` | New invariant **9**: the browser handoff is a manifest invariant, with the decoded-path rule and the crash-fix-3 reference, so the next maintainer cannot silently reintroduce it. |
