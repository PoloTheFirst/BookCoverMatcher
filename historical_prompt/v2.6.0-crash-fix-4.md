## 2. Issue A — October and November missing dark background

### Observed problem

The graph's dark background is applied to most of the contribution graph, but the October and November area remains without the expected dark background.

This suggests that the dark-theme transformation may not cover all graph elements, or that some elements are rendered through a different SVG structure or styling path.

Do not assume that the problem is caused by the month labels themselves. Inspect the actual rendered area.

### Investigation

Trace the full graph rendering pipeline:

1. Identify the original contribution graph SVG and its dimensions/viewBox.
2. Inspect all SVG elements that contribute to the October and November area.
3. Identify background rectangles, group elements, paths, masks, clipping paths, CSS classes, inline styles, and inherited fill values.
4. Determine whether October and November are outside the background element's bounds or belong to a separate SVG group.
5. Check whether the dark-theme transformation only modifies selected elements or relies on incomplete selectors.
6. Check whether SMIL frame generation, SVG rewriting, or animation-frame caching drops or overrides background styling.
7. Check whether the affected area is actually transparent, white, or rendered with a different color.
8. Compare the original SVG, transformed SVG, and actual device output.

Record the exact elements and attributes responsible for the uncovered area.

### Implementation requirements

Apply a complete and reliable dark background to the entire intended graph canvas.

- Cover all contribution-grid regions, including October and November.
- Cover the complete intended graph bounds, not merely the previously covered months.
- Use the graph's actual SVG coordinate system and viewBox.
- Ensure the background is behind all contribution cells, labels, and animated elements.
- Preserve clipping, masks, transforms, and SVG grouping behavior.
- Ensure the background is present in every generated animation frame.
- Prevent a white or transparent flash during initial rendering, animation, navigation, or resume.
- Keep the background dark in both Android light mode and Android dark mode.
- Do not change the global application theme.
- Do not cover, obscure, or reduce the contrast of the contribution cells.
- Do not use a Compose overlay as a superficial patch if the underlying SVG rendering can be corrected safely.

Prefer a single full-canvas background element or an equivalent robust SVG-level solution, provided it does not interfere with the existing animation.

Do not hardcode month-specific patches for October and November if the actual defect is incomplete graph-canvas coverage.

There is an unnecessary extra row at the very bottom of the contribution graph.

The user has explicitly clarified that this row is surplus heat-map layout. It is not a missing-bug indicator, a placeholder for missing contribution data, or a row that should be preserved for semantic reasons.

Remove the surplus row while preserving every valid contribution cell.

### Investigation

Do not immediately crop the bottom of the rendered image. First determine why the row exists.

Inspect:

1. Original SVG viewBox and declared dimensions.
2. Contribution-grid group dimensions and transforms.
3. Number of heat-map rows in the source.
4. Actual row positions and spacing.
5. Whether the bottom row contains real contribution cells, duplicate cells, an empty layout row, or an artifact introduced by SVG transformation.
6. Whether the row is generated by a Markdown/README conversion or by the Pacman animation transformation.
7. Whether SMIL animation changes the bottom boundary or creates an extra visible strip.
8. Whether the Compose image aspect ratio or scaling introduces the apparent row.
9. Whether clipping or viewBox expansion adds space below the intended grid.

Determine whether the surplus row is present in the source or introduced by the Android rendering pipeline.

### Important distinction

Do not remove a legitimate contribution row simply because it appears at the bottom.

Count and map the actual heat-map rows before changing anything.

The expected result is the original intended contribution grid with the redundant bottom row removed. Preserve the correct weekday/week layout and all valid contribution data.

- Preserve all valid contribution cells.
