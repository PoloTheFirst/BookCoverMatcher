### 1. Root cause of the mismatch (reproduced, not assumed)

The model package's `inference.yml` was never truncated. The old PowerShell extraction lost **exactly four** entries — re-running the `ae362fd` loop against the same file now yields **18,704** and lists them:

| Lost entry | Why |
|---|---|
| `U+3000` (entry 1748) | raw line is `- <U+3000>`; `String.Trim()`/`str.strip()` treat it as whitespace → line becomes `-` → skipped |
| `U+303D` 〽, `U+FF9E` ﾞ, `U+FF9F` ﾟ | lines *do* start with `- `, but PowerShell's **culture-sensitive** `StartsWith('- ')` returns **False** for these collation-ignorable characters (`Ordinal` = True) |

Class indices are positional, so every character after 1748 was shifted — exactly the "plausible but wrong" failure the guard existed to refuse. A third defect existed in the crashed session's extractor (`unquote()` used `strip()`, emptying `U+3000`); fixed.

### 3. Implementation (beyond the dictionary)

* **`rec`**: the graph already ends in `Softmax`, so its output was being softmaxed twice — every line printed **0.0 %** confidence (text was fine, scores ≈1/18,710). Now a probability row is detected and used as-is; non-finite scores are rejected; strict class-count refusal retained. +3 tests.
* **`engine`**: `OcrEngine::open()` could only ever succeed **once per process** (`ort` allows one environment); now a process-wide environment is cloned, and a failed init is not cached. Added public `detect()` + `DetectorReport` (reused by `recognise()`).
* **Docs/tests/tools**: `tests/dictionary.rs` (new, 10 tests), unblocked `real_models`, fixed extractor, hash-verifying fetch script, new `tools/make-ocr-crops.py`, README/lib.rs/report updated, `.gitattributes` pins LF so the dictionary hash reproduces.
