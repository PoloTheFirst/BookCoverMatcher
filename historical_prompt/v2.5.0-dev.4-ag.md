## 1. Implementation summary

v2.5.0-dev.4 makes a SauceNAO result as usable in the collection workflow as an IQDB result.

1. **Pictures.** Every discovery card has a fixed 60×82 dp picture box that fills from the provider's own result image
   first and, when that is absent or unfetchable, from the result page's **declared** image metadata (Open Graph →
   Twitter card → `image_src`/`itemprop`). Retrieval is a new, deliberately narrow pipeline
   (`SafeImageUrl` + `DiscoveryWebFetcher` + `CoverImageExtractor` + `DiscoveryCoverLoader`) with per-hop SSRF
   validation, byte caps, timeouts, content-type checks and header-only decode validation. A missing picture is a
   normal state (`NOT_REQUESTED` / `LOADING` / `AVAILABLE` / `UNAVAILABLE` / `FAILED` on the candidate) and never
   invalidates a result.
2. **Dismissal.** Every card a provider reported — SauceNAO cards included — now has the rubbish bin IQDB cards already
   had, with a provider-specific accessibility label.
3. **Per-card bookmark and wishlist.** `Bookmark` and `+ Wishlist` on every discovery card, reusing the existing
   `WishlistRepository` bookmark path and the existing folder picker; the chips show `Bookmarked ✓` / `In wishlist ✓`.
4. **Profile-wide wishlist.** `addResultProfileToWishlist` now includes the eligible discovery candidates
   (offline top-5 + platform results + discovery, deduplicated).
5. **Rename.** `Bookmark all results` → `Bookmark all platform results` (Online tab and the search's Bookmarks tab).
6. **New bulk action.** `Bookmark all discovery results`, inside the reverse-image section, with per-provider counts.

All of it was verified on the emulator with a **live SauceNAO search** (8 hits) and a **live webpage image extraction**
(`www.python.org`), plus **914 unit tests** and a clean debug build.

## 4. SauceNAO image extraction implementation

`DiscoveryCoverLoader.load(providerImageUrl, pageUrl)`:

| Priority | Source | Detail |
|---|---|---|
| 1 | `DiscoveryImageSource.PROVIDER` | `ReverseImageHit.imageUrl` (`header.thumbnail` from the SauceNAO response) |
| 2 | `WEBPAGE_OPEN_GRAPH` | `og:image:secure_url`, then `og:image` |
| 3 | `WEBPAGE_TWITTER` | `twitter:image`, then `twitter:image:src` |
| 4 | `WEBPAGE_IMAGE_SRC` | `<link rel="image_src">`, `itemprop="image"` |
| — | `null` | card keeps `no image` / `loading…` / `not loadable` |

* `CoverImageExtractor.fromHtml` parses `<meta>`/`<link>` attributes (any order, single or double quotes, any case) and
  returns the **declaring metadata** with the URL, so provenance is real. Relative and protocol-relative URLs are
  resolved against the page; anything that does not pass `SafeImageUrl` is dropped. The first `<img>` is never used.
* `SafeImageUrl` requires HTTPS, no credentials, the default port, a dotted host and a public address — `localhost`,
  `*.local`/`*.internal`, `10/8`, `100.64/10`, `127/8`, `169.254/16` (cloud metadata), `172.16/12`, `192.168/16`,
  `>=224`, `::1`, `::`, `fc00::/7`, `fe80::/10` and IPv4-mapped IPv6 are refused.
* `DiscoveryWebFetcher` sets `instanceFollowRedirects = false` and re-issues each validated `Location` (≤ 3 hops), so a
  `302` to a private address cannot pass. Page cap 512 KB (**truncated** — the metadata is in the head, and truncating
  instead of failing is what made a real >512 KB page work at all), image cap 400 KB (**refused** — half a JPEG is not
  an image), connect 8 s, read 10 s, content type must be markup or `image/jpeg|png|webp|gif`.
* `DiscoveryCoverLoader.isUsableImage` decodes header-only (`inJustDecodeBounds`) and rejects non-images and anything
  over 4096 px on an edge. Bytes go into the existing `core/online/BoundedImageCache` (LRU, byte budget, per-entry
  ceiling); the only new state is a page → declared-image index (≤ 32 entries), so a second card from one page does not
  refetch the HTML. Dismissal evicts nothing.
* Loading runs on `Dispatchers.IO`, one candidate at a time, in a job cancelled by a newer search and keyed to the
  search generation, so a stale answer can never decorate a newer result list. Only host names, byte sizes and failure
  reasons are logged (`Log.d("DiscoveryCover", …)`).

## 5. SauceNAO dismissal implementation

* `ui/ReverseImagePanel.kt` draws the 36 dp `Icons.Filled.Delete` button for **every** card whose
  `ReverseCandidateUi.isDismissible` is true (any card a reverse-image provider reported), with
  `contentDescription = candidate.dismissLabel`:
  * `Dismiss IQDB result` — IQDB only (unchanged label and behaviour from dev.3);
  * `Dismiss SauceNAO result` — SauceNAO only (new in dev.4);
  * `Dismiss discovery result` — a card both providers reported, which is **one** card holding both references, so
    "the whole card" is the only honest description.
* `OnlineSearchController.dismissCandidate` now delegates to `CandidateLists.dismiss`, which removes exactly that key
  from the pasted and searched lists and returns `null` when the key is absent.
* No data is deleted: decision log, workbook, wishlist, bookmarks and cached pictures are untouched.
* **Anti-resurrection.** `CandidateLists.patch` returns `null` for a key that is no longer present, so a picture (or any
  other asynchronous answer) that arrives after a dismissal is dropped; the search generation guard already dropped
  stale runs. Tested in `DiscoveryCandidateListsTest`.

## 6. SauceNAO bookmark and wishlist implementation

* `ReverseCandidateUi.toDraft()` (in `OnlineSearchUi.kt`) maps a candidate onto the existing `ItemDraft`:
  `providerKey = DiscoveryDrafts.fingerprintOf(key)` (**the candidate's own key**, lower-cased), `provider` =
  `SauceNAO` / `IQDB` / `SauceNAO + IQDB`, `identifier` = the product id when present, `authors`/`circle` only when the
  provider sent them, `matchType = VISUAL` + `matchTypeVerified`, `thumbJpeg` = the picture **when one was obtained**.
  Nothing is fabricated: unknown fields stay null/empty.
* `MainViewModel.toggleDiscoveryBookmark(candidate)` — `Bookmarks` membership only, idempotent, reuses
  `WishlistRepository.bookmark` / `bookmarkExisting` / `removeBookmark`, and looks the item up by fingerprint **or by
  source URL** first so an existing record gets the membership instead of a second record.
* `MainViewModel.addDiscoveryToWishlist(candidate)` — opens the *same* `openPicker` (`ADD_ITEMS`) every other card uses.
  No SauceNAO-specific persistence exists anywhere.
* UI chips read `Bookmarked ✓` / `In wishlist ✓` from the existing `bookmarkedKeys` / `wishlistedKeys` sets
  (`item.fingerprint`), which is why the candidate key had to be the fingerprint.
* Profile isolation is inherited from the repository; `bookmarkAll`/`addDrafts` already deduplicate by fingerprint.


## 7. Profile-wide wishlist aggregation changes

`MainViewModel.addResultProfileToWishlist` previously built its drafts from `lastRanked` + `CatalogueUi.Found.items`
only. It now adds `storableDiscoveryCandidates()` (discovery candidates that are not `REJECTED` and carry a title,
product id or link) and deduplicates the whole list by `ItemDraft.fingerprint` before opening the picker. SauceNAO is
included whenever SauceNAO participated, no results are invented when it did not, and a rejected card is never added.
Partial failure semantics are unchanged: the picker writes once, through `WishlistRepository`, and reports
`added` / `alreadyThere`; a storage failure surfaces as an error toast rather than a false success. Repeated runs add
nothing twice. Measured on the emulator: `6 result(s) will be saved as one session` for 5 platform results + 1
discovery candidate (dev.3 would have said 5).

## 14. Known limitations and deferred work

1. **Not every result has a picture.** A page may declare no image, refuse the request (observed: `HTTP 429` from
   `upload.wikimedia.org`), or serve a format the app does not decode. The card then shows `no image`; a valid,
   bookmarkable result is never removed.
2. **DNS is not resolved before connecting.** A hostname that resolves to a private address at fetch time is outside
   `SafeImageUrl`. The mitigation is that only provider-supplied or page-declared URLs are fetched, with caps and
   timeouts. Documented in `ONLINE_SEARCH.md` §12.2 and in the changelog.
3. **Dismissal is in-memory.** No persistent block-list was introduced (the prompt forbids adding one just for the
   control); a later search may show the same result again.
4. **`UNAVAILABLE` and `FAILED` are not yet distinguished by the loader.** Both states exist on the model, but the
   loader reports every failure as `UNAVAILABLE` because it deliberately swallows the reason; the states are ready for a
   later refinement (the reason *is* logged for support).
5. **A card both providers reported is now dismissible as a whole** (`Dismiss discovery result`). dev.3 withheld the
   control there; dev.4 requires every SauceNAO card to have one, and that card is one record holding both references.
6. **Quota was not re-read** this round, and a *second* live call after replacing the key was still not re-run (the key
   was not replaced this round).
7. Deferred from earlier rounds and untouched: per-card `CollectionStatus` / OpenCLIP evidence, and any genuinely
   permitted automated IQDB route.
