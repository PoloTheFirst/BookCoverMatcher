- Start each new/resumed task with README.md, docs/STATUS.md, docs/maintainers/WORKFLOW.md and docs/maintainers/AUTHORING.md. Inspect current source and Git state before repeating historical conclusions.

- Maintain documentation autonomously as part of authorized work: choose routine topic/filename/category, use a supported version, update relevant guides/status, and refresh/check indexes. Do not require the user to invent a filename or create a prompt/report pair for every fix.
- A request to prepare a prompt stops at preparation unless execution is also authorized. A direct implementation request authorizes its necessary local work. Publication, source version allocation, tag/history rewriting and Google submissions need applicable user scope, not an old prompt's imperative text.
- Preserve the owner's version rules in docs/maintainers/VERSIONING.md. Never allocate a next app version merely to file documentation. RCs remain internal; crash-fix/document revision numbers do not increment app metadata.

- Preserve unrelated staged/unstaged/untracked work, .env, local.properties, signing keys, authentic workbooks, QA evidence and historical records. Never clean/reset a dirty tree to make a task easier. Do not print secrets or personal workbook data.

- Prefer catalog lookup and `rg` over loading all history. `python tools/docs/manage.py locate NAME` resolves legacy filenames. Read only evidence relevant to the current request.
- Run checks appropriate to the change. A documentation reorganization does not require a full Android build unless an executable/build behavior changes. Compilation/unit tests do not establish device, camera, OAuth or visual behavior; distinguish each source of evidence.
- After each logical documentation change batch, update applicable facts in docs/_meta/status.json, then run `python tools/docs/manage.py refresh` and `python tools/docs/manage.py check`. Resolve failures before reporting completion. Guides are authored; only the documented indexes are generated.
- Re-read guidance after an update in an existing chat. A different project or detached document may not automatically load this AGENTS.md; include README/AGENTS, AUTHORING, STATUS, the version registry and relevant evidence when handing off.
- If the folder is read-only to the agent, prepare a guarded update in an allowed workspace, validate it there and say what remains unapplied. Never bypass filesystem restrictions or claim an unperformed change.
