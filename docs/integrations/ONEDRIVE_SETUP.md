## Registration and authentication

BookCoverMatcher uses an Android public client and personal Microsoft accounts. In Microsoft Entra app registration, the supported account types must include personal Microsoft accounts. Register the Android platform with package `com.bookcovermatcher` and the actual signing certificate hash for the installed build. Use the portal-generated redirect URI. The app uses the `consumers` authority via MSAL's `PersonalMicrosoftAccount` audience; do not substitute a school tenant. Request delegated `Files.Read` and `User.Read`. No client secret belongs in the APK. Keep local configuration in the ignored `.env`; never paste credentials or tokens into reports.

The signing identity delivered by Google Play can differ from a local debug or upload certificate. Register its Android redirect separately before testing that distribution. Do not change registrations or add write permissions merely because a download failed after successful login and folder browsing.

## Sign-in succeeds and folders load, but downloading fails

Folder listing and file delivery are separate requests. A rejected storage download is not proof that the Microsoft login expired. Older versions mapped every download HTTP 401 to that message.

The local dev.2 recovery now:

1. Requests the file through authenticated Microsoft Graph `/content`, accepting binary content or its documented redirect.
2. Follows a valid HTTPS storage URL without forwarding the Graph access token.
3. For a storage HTTP 401 on exactly `https://my.microsoftpersonalcontent.com` (default HTTPS port), if its URL contains one valid `tempauth` value, retries once using only that URL-scoped value in the Authorization header. This is an experimental compatibility path based on a firsthand report, not a documented change to Microsoft Graph permissions. Every redirect is followed manually with the header removed. Other hosts never receive it.
4. On remaining HTTP 401/403, requests fresh item metadata with `id,@microsoft.graph.downloadUrl` and tries the supplied URL once, before writing any bytes.
5. Keeps genuine metadata authentication failures as sign-in errors. If metadata succeeds but storage still rejects the file, reports a file-delivery failure without treating the account as expired.

Temporary URLs are neither persisted nor logged. Recovery is bounded and does not retry a partially written stream. Existing validated local copies remain intact. This corrects a reproducible client error and adds a documented alternative download route; it is not proof that the owner's Vivo failure is resolved. Tests simulate service responses; no live account download was performed for this change.

Install the updated debug APK over the compatible existing build, sign in if needed, and retry one workbook. No USB debugging or new account permission is required to try this build. If the service still rejects it, download using OneDrive's own app and use Saved Workbooks > Import as a temporary fallback.

## Policy-change interpretation

The current v1.0 API documents `Files.Read` for personal-account downloads and a short-lived preauthenticated URL. Microsoft's October 8, 2026 announcement describes removal of preauthenticated URLs beginning April 1, 2027 and tenant opt-in controls. It is not evidence that a specific personal account's current failure is caused by that change. The client already accepts direct HTTP 200 content. Do not forward a Graph token to storage hosts or switch production traffic to a beta API as an assumed fix. The narrow personal-host compatibility retry above supersedes the previous decision to avoid a URL-capability header entirely; it is bounded, host-restricted and unverified on the owner?s Vivo.
