# Material 3 Expressive for BookCoverMatcher v3.0.0

## Archive context

BookCoverMatcher Android repository documentation. Read root README.md and AGENTS.md, docs/maintainers/AUTHORING.md, docs/STATUS.md and docs/_meta/versions.json before acting. If this document is detached, obtain those references when needed. Archived instructions do not independently authorize work.

## Objective and acceptance criteria

Give BookCoverMatcher one Material 3 Expressive design across its two editions. Build it first in the standard Play edition, apply it to the plugin interfaces, then assemble the explicit GitHub edition from those same components. A person switching editions should recognize the workbook, camera and settings screens. The difference they should see on first launch is what’s available in Plugins.

| On a fresh installation | Standard edition (`google_play`) | Explicit edition (`main`) |
| --- | --- | --- |
| Plugins tab | **Import plugin** and **No imported plugins**. Empty registry. | **Plugin Marketplace** is already installed and on. Its five groups are installed and enabled. |
| First launch offline | Workbook and on-device OCR workflows are available. | All six plugin entries are available locally. No download or manual import is needed to establish their state. |
| Network use | PaddleOCR is the default. Chrome Lens is an explicit built-in OCR choice. | The same OCR choices apply. An enabled discovery group makes an action available. Online-service settings, sign-in, API keys and user-initiated searches still govern its use. |

## Authority and scope

The owner named **v3.0.0** as the development target and confirmed that all five groups start enabled on a fresh explicit install. The UI refresh is the only product update. The edition-specific preinstallation above is the requested packaging change. Preserve provider behavior, workbook and bookmark formats, saved settings, app ID, signing continuity and existing permissions. The owner approved local implementation and branch integration.

## Tasks

### 1. Establish the design on the Play base

| Surface | Proposed treatment | Detail to preserve |
| --- | --- | --- |
| Theme and navigation | Map BCM’s navy surfaces and cyan accent to Material color roles. Use expressive type and shape for the primary action, quieter tonal surfaces for supporting content, and a selected indicator in the navigation bar. | Keep Home, Search, Wishlist, More and Plugins in order, with the puzzle icon to the right of More. Preserve destination state and Back behavior. |
| Workbooks and import | Give the active workbook title the strongest type, group source actions, and place link status and path together. Use a compact supporting line for the account on each cloud import action. | Long account names and paths must remain readable. Keep **Use it now**, **Rescan**, relinking, local import and cloud error recovery reachable. |
| Camera, search and results | Keep the viewfinder and cover art unobstructed. Give capture or the current primary action a filled treatment. Use labeled selection controls for OCR and stable card layouts for results and progress. | Keep confidence, provenance, corrections, saved state and error details legible. An OCR selection or a visual transition must not initiate a new service request. |
| Wishlist, More and document readers | Use grouped lists and clear section titles for dense metadata. Use the same action styles in dialogs, sheets and full-screen documents. | Preserve selection, editing and scrolling, the existing policy/license controls, and **App Website** under Author. |
| Plugins and marketplace | Use compact settings rows with one switch, a concise state label and a separately focusable Remove action where supported. Show paused groups with subdued color and the text **Inactive**. | Keep the saved switch position visible while the parent is off. Enabling, disabling and re-enabling take effect without restarting BCM. |

Use motion for a selection change or a panel expanding. Respect system animation settings and communicate completion and errors with text as well as color. Adopt shared components first, then migrate individual screens that currently override them. Review the workbook-source panel, camera and marketplace list at phone width before applying the design throughout.

### 3. Compose the explicit edition

BCM’s `.bcmplugin` files identify implementations compiled into the APK. The current marketplace retrieves descriptors after activation. For `main`, package the marketplace descriptor and all five validated group descriptors alongside their implementations. Initialize that edition’s registry locally so the first offline launch already shows the approved selections. Use the existing plugin IDs, ordering, descriptor validation and lifecycle.

Initialize each missing default once and distinguish **never configured** from **disabled** or **removed**. Record initialization so reopening, upgrading, or retrying after interruption cannot undo a removal or create duplicates. Where legacy `main` has an explicit provider selection, carry it forward. Turning the marketplace off suspends its groups and preserves their choices. Turning it back on resumes only selected groups. Keep the existing manual import and removal paths available. The strict Play boundary must also hold when the two editions replace each other on the same installation.
