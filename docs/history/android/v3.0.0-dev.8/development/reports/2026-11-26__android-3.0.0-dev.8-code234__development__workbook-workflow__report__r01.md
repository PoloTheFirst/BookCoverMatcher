# Dev.8 workbook and search workflow

## Archive context

BookCoverMatcher Android repository documentation. Read root README.md and AGENTS.md, docs/maintainers/AUTHORING.md, docs/STATUS.md and docs/_meta/versions.json for current context. This report records evidence, not new authorization.

## Outcome

BCM and BCM Plus dev.8 (234) are built and signed locally. Both passed the Home workbook and More settings checks on Android 16.

## Scope and baseline

This report covers the 26 November 2026 request for Home, search buttons, language-field wording, the Author page and policy review. This edition’s working tree is based on `google_play` at `3e322060a1d5d05b25b9c389e0d06a3a8b8196cb`. The previous public version was dev.7 (233).

## Changes and decisions

- Home places **Workbook comments & images** beneath workbook selection. The whole row opens the existing viewer. With no selection it explains what to choose. It can also open an already selected workbook while the matching model is unavailable. Workbook storage, notes, media, catalogue tables, insights and export use their existing code paths.
- **Search selected platforms** and **Search by this cover** keep their existing actions and fills. Their call sites now use the shared button’s default of no outer shadow.
- In More, **Language printed on the cover** explains automatic detection and the `ja` source example. **Translate into** explains that a blank keeps the original text and `en` requests English. The Lens bridge passes these choices separately. PaddleOCR runs locally without these hints or translation.
- The Author README starts expanded. Users can collapse and reopen it. The existing startup refresh handles the author content.
- The shipped dev.7 APKs still contained v2.7.0 policy text. The website source already described the current standard/Plus differences, including online providers and optional image transfers. The new UI adds no data flow or obligation. Both canonical documents now carry those disclosures forward at revision `2026-11-26.2`. The privacy text explains that displaying the expanded author content and refreshing it at app startup are separate operations.

## Verification and evidence

- Ran the edition’s Gradle debug assembly, JVM tests, debug lint, Android test assembly and signed release assembly. BCM passed 1,271 JVM tests with 12 skipped and 0 lint errors (54 warnings, 2 hints). BCM Plus passed 1,444 with 16 skipped and 0 lint errors (49 warnings, 2 hints).
- Ran `WorkbookImportNavigationDeviceTest` on an Android 16 emulator using the two debug variants and a synthetic workbook. All four tests passed per edition. They verified the disabled Home entry before selection, the identity of the workbook opened from Home, return to Home, both language hints, Author controls, existing simulated cloud import navigation and local grant states.
- Checked both APKs with `aapt2 dump badging`, `apksigner verify --print-certs` and `zipalign -c -P 16 4`. Each has package `com.bookcovermatcher`, code 234, the expected version name and the dev.7 release certificate. Native libraries and packaged OCR/model/plugin files compared byte-for-byte with the respective dev.7 APKs. Bundled privacy and terms match their canonical release sources.
- BCM APK SHA-256: `31b7c9b007e16e449e76f189150d81de1318897624b376318ff530daed09b546`. BCM Plus APK SHA-256: `149e75e02072c7b815fc6d40542c24f1b3c6c2d1cef906dfb022e2147661185d`.
- Updated the user guide, version registry, status and release changelog. Documentation uses `python3 tools/docs/manage.py refresh` and `python3 tools/docs/manage.py check`.
