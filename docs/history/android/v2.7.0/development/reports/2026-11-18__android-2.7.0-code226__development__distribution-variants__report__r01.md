# Play and GitHub distribution variants

## Archive context

BookCoverMatcher Android repository documentation. Read root README.md and AGENTS.md, docs/maintainers/AUTHORING.md, docs/STATUS.md and docs/_meta/versions.json for current context. This report records evidence, not new authorization.

## Outcome

Created local `google_play` branch and implemented separate `play`/`github` build variants. GitHub retains all providers. Play excludes public catalogue discovery and shortcuts while retaining SauceNAO and IQDB as explicitly requested. Nothing was published or installed; Play eligibility is not established.

## Scope and baseline

Owner authorized implementation after the plan, with no publication and preservation of workbook data/update compatibility. Base HEAD is `9a5318b49f412c25fcd77c8fd3186867f34255f6`; extensive pre-existing tracked/untracked work was preserved. Version remains 2.7.0/code226. The branch change does not commit or isolate existing dirty files from that working tree. Neither the website nor private account configuration was modified.

## Changes and decisions

- Flavor source sets select catalogue registries, capability metadata, network adapters and help text. GitHub retains all 11 catalogue/shortcut registrations and existing reverse-image providers. Play has empty catalogue registries; DLsite, Melonbooks, Google Books and Open Library network adapters are excluded from its APK.
- Play hides catalogue controls, disables automatic/secondary catalogue requests even with restored GitHub preferences, and selects on-device PaddleOCR without overwriting the stored GitHub OCR/provider settings. Shared Python dependencies remain packaged.
- Play uses neutral bookmark-form examples; GitHub retains the original examples. Artifact inspection confirms the explicit sample text and adult-site example URL are absent from Play. Shared placeholder tests now assert the shared behavior; flavor tests check their respective examples.
- Saved catalogue records are presented as unavailable in Play with no image, metadata or link; the records are not deleted or rewritten. Opening their editor is also blocked in Play. Workbook matches, custom bookmarks and SauceNAO/IQDB-provenance results remain usable. This does not sanitize arbitrary personal files, URLs or reverse-image results.
- Application ID, version, release signing configuration, persistence schema and preference keys are unchanged. No owner device/app data, workbook, account credential or keystore operation was performed.
- Added variant regression coverage, moved catalogue-specific tests to GitHub, and added a compiled Play instrumentation test for restored preferences/controller guards.
- Added an explicit failing Play publication check dependent on the existing failing auth check. Local builds remain possible; these tasks are not an automatic barrier to manual uploading.

Retained reverse-image imagery/links, ratings, Data safety, public reviewer URLs and edition-specific policy/website disclosures still require review.
