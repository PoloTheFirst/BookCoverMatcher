# Indexed platform groups on four local plugin branches

## Archive context

BookCoverMatcher Android repository documentation. Read root README.md and AGENTS.md, docs/maintainers/AUTHORING.md, docs/STATUS.md and docs/_meta/versions.json for current context. This report records evidence, not new authorization.

## Outcome

The GitHub edition now offers independent platform groups through manual descriptor import. In a local combined build, the emulator displayed all eleven platforms in the approved order. Each plugin branch carries one concrete group and its own descriptor. Doujinshi.info remains the final, ungrouped browser shortcut.

## Scope and baseline

Owner-approved revision 2 of the DLsite working prompt targets Android 2.7.0, code 226. The starting implementation is `cc7cec5`. Shared group routing was developed outside `feature/plugin-framework`. Local provider commits are `79223f5` (ordinary libraries), `b6390e7` (DLsite), `6cd6ac4` (doujin shops) and `067b1d6` (database shortcuts). The local DLsite branch is now named `plugin/dlsite-fetch`. The existing remote DLsite ref retains its previous name.

## Changes and decisions

The GitHub build generates typed registrations from the group source files present in the checkout. Each group declares its numeric platform index, ordered provider specifications and, for catalogue search, its adapter factory. The screen and controller derive platform availability from active contributions. The original query encodings, site destinations, provider IDs and adapters carry forward. The stores retain group switch state and explicit library selections independently. A previously imported DLsite descriptor still works. MyAnimeList opens its manga search on myanimelist.net.

## Verification and evidence

- Built each independent GitHub debug APK and ran its debug unit suite. Verified each generated registry contained the single expected group class.
- Tested all four groups together on a detached local checkout. GitHub and Play debug/release builds passed. Both debug unit suites finished with zero failures or errors. GitHub reported 1,453 tests with 16 skipped. Play reported 1,339 with 12 skipped. Lint reported zero errors and 59 warnings per edition. All four APKs have application ID `com.bookcovermatcher`, version 2.7.0 / code 226.
- Inspected DEX class definitions in all four APKs. Both GitHub APKs contain four concrete group definitions and the three original fetch adapters. Both Play APKs exclude all seven classes.
- Ran five GitHub and one Play instrumented tests on a disposable read-only API 36 emulator. Verified settings persistence, library selection and master switches, OCR/cache behavior, cancellation, delayed replies, bookmark/workbook preservation and Play's rejection of all four descriptors. Intercepted external browser intents on the emulator so no shortcut site was visited.
- Used BCM's actual Android file picker for all four descriptors. The previously imported DLsite file was recognized. Enabled groups in reverse index order through Plugins, then read the rendered Platforms list from Android accessibility. It showed Open Library, Google Books, DLsite, Melonbooks, Suruga-ya, Toranoana, nhentai, E-Hentai, Doujin no Mori, MyAnimeList and Doujinshi.info.
- The tested combined GitHub debug APK has SHA-256 `c4e5a4b0f7785d15098d649ef986b17bfd7cbb413c152c30ab923d4a4ca476cf`. The local QA copy and its four descriptors are under the ignored `app/build/outputs/platform-group-qa/` directory.

## Outstanding work and risks

These checks establish local routing, persistence, ordering and packaging. External catalogue availability and Play review were outside this migration. The marketplace remains deferred.
