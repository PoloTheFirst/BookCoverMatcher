# GitHub marketplace for manually imported plugin descriptors

## Archive context

BookCoverMatcher Android repository documentation. Read root README.md and AGENTS.md, docs/maintainers/AUTHORING.md, docs/STATUS.md and docs/_meta/versions.json for current context. This report records evidence, not new authorization.

## Outcome

The GitHub edition on `plugin/plugin-marketplace` includes an optional marketplace for the four platform groups. Users manually import the marketplace, enable it and choose which descriptor to save. Each provider has a separate import and switch.

## Scope and baseline

The owner approved revision 3 of the DLsite working prompt and remote delivery of this branch. The integration commit `ea8daa0` combines the four provider tips specified in that prompt. Android identity remains `com.bookcovermatcher`, version 2.7.0 (226), with the existing signing configuration. The change adds no workbook or bookmark migration.

## Changes and decisions

The GitHub registration contributes a panel to the Plugins screen. The offline catalogue describes each group and checks its availability against the installed registry. Saving contacts GitHub for the selected file at the pinned commit. BCM bounds the response to 256 bytes, validates its format and expected ID, and offers the Android document creation dialog. Import uses the existing local picker and upgrade rules. The Play source set supplies an empty registration list and no marketplace UI. See the [plugin guide](../../../../../guides/BUNDLED_PLUGINS.md).

## Verification and evidence

- On CachyOS, Gradle assembled GitHub and Play debug/release APKs and both debug instrumentation APKs. The debug unit suites reported 1,456 GitHub tests (16 skipped) and 1,339 Play tests (12 skipped), with zero failures. Debug lint reported zero errors and 59 warnings for each edition.
- DEX inspection found the marketplace implementation classes and pinned GitHub route in both GitHub APKs and zero matches in both Play APKs. Output metadata confirmed the expected app identity and version in all four.
- The four pinned files were fetched from GitHub and compared byte for byte to their branch descriptors. Unit fixtures checked catalogue order, URLs, CRLF preservation, mismatch, malformed/oversized input and availability states.
- On a disposable API 36 emulator, the Android picker imported the marketplace. Cancelling a save left the provider unimported. Saving the live ordinary-library descriptor produced the expected filename and exact bytes, and still left the provider unimported. A separate picker import exposed its switch. The provider could be toggled live and retained its enabled choice across restart with the marketplace disabled. Offline catalogue access and a failed fetch preserved the import. A temporary APK omitting the ordinary-library group displayed the compatibility message with the prior choice present. The complete GitHub APK was rebuilt after this check.
- Android instrumentation passed five GitHub cases covering group order, the trailing Doujinshi.info entry and DLsite behavior, plus one Play case covering restored GitHub preferences and rejection of unsupported descriptors, including the marketplace. Tests used the isolated emulator and fixture data.

## Outstanding work and risks

Live saving depends on GitHub serving the pinned file and the chosen Android document provider accepting writes. The emulator covered successful writes and user cancellation. A document provider refusing a write after selection was not simulated. Lint warnings remain. Release signing, tags, publication and Play submission are outside this branch delivery.
