# Bundled plugins and live settings switches

## Archive context

BookCoverMatcher Android repository documentation. Read root README.md and AGENTS.md, docs/maintainers/AUTHORING.md, docs/STATUS.md and docs/_meta/versions.json for current context. This report records evidence, not new authorization.

## Outcome

The GitHub and Play debug apps expose a live Demo card switch in Plugins. Release builds use the same framework with an empty registry. The card appears and disappears in the existing activity and the app restores the saved choice on launch.

## Scope and baseline

The owner approved local implementation and documentation on feature/plugin-framework at c2141f4 for Android 2.7.0/code 226. The current worktree contains the changes. The app ID and signing configuration carry forward from that commit.

## Changes and decisions

The plain Kotlin/JVM plugin-api and plugins:demo modules define the contract and demonstrate a local read-only card. Debug and release source sets register trusted bundled factories. The host validates IDs, rejects duplicates, checks API range and capability, and serializes activation per ID. Each activation gets a fresh instance and a cancellable coroutine. The host limits its wait for startup and cleanup, and prevents a second activation from overlapping unfinished cleanup. Dedicated atomic preference files preserve individual choices independently of all workbook and provider state. Compose observes the runtime directly.

## Verification and evidence

On CachyOS, Gradle assembled both debug and release APKs, ran both debug unit suites and completed both debug lint tasks. Play recorded 1325 passing tests and 12 skips. GitHub recorded 1434 passing tests and 16 skips. Both had zero failures and errors. Four new manager tests per suite cover registry validation, restoration, duplicate requests, activation failure and retry, preference write failures, and overlapping requests during slow cleanup. Gradle and test reports are under app/build.

On the API 36 x86_64 emulator, both final debug builds installed as matching-signature updates. Enabling displayed the card with the original app PID. It survived switching tabs and process recreation. Disabling at 150% font hid the card, and another process restart restored the off state. The final run restored the original font setting. An earlier emulator disconnect interrupted the first Play pass. Both final APKs passed the repeat run.

DEX inspection found the demo class in both debug APKs and neither release APK. Both release manifests report com.bookcovermatcher, 2.7.0/226. All 63 provider and edition source hashes matched the prior baseline. Workbook store and authentication code were outside the diff. Source licensing and documentation checks passed.

## Outstanding work and risks

The emulator test covers debug updates. Installing a new release-signed build over a physical device installation remains unverified. Trusted plugins execute inside the app process and must implement cooperative cleanup. The implementation phase covers bundled modules only. The first production plugin, external imports and downloads remain future work.
