# Manual DLsite plugin import and live switching

## Archive context

BookCoverMatcher Android repository documentation. Read root README.md and AGENTS.md, docs/maintainers/AUTHORING.md, docs/STATUS.md and docs/_meta/versions.json for current context. This report records evidence, not new authorization.

## Outcome

Implemented manual plugin import and live DLsite catalogue switching on the local `plugin/dlsite` branch for Android 2.7.0 (226). The GitHub edition accepts the DLsite descriptor. Play rejects it. The emulator is running the GitHub debug build with DLsite imported and switched off.

## Scope and baseline

The owner approved implementing the versioned DLsite plan at framework checkpoint `1b3dbee` and specified manual import for every plugin. Use Kotlin `.kt` for implementations and a two-line `.bcmplugin` file for user import. Executable implementations ship in the matching APK. A new implementation requires a new app build.

## Changes and decisions

- Host API 2 supports information cards and catalogue contributions. First import obtains the explicitly saved DLsite preference. A missing preference starts off. A stored plugin switch takes precedence on later imports and launches.
- GitHub constructs its DLsite adapter on activation. Eligible catalogue and OCR-triggered searches use it. Disabling removes its platform and transient results. Cache and callback checks distinguish each activation, including a rapid off/on cycle. Completed results with unrelated provenance stay visible.
- The local demo also requires manual import in both debug editions. Workbook and bookmark storage, identity, version and signing configuration retain their existing formats.

## Verification and evidence

- Built GitHub and Play debug and release APKs with Gradle. Inspected DEX class definitions in all four APKs. Both GitHub artifacts contain the DLsite activation and HTTP adapter. Both Play artifacts exclude those classes. Only the debug artifacts include the demo implementation. All four report `com.bookcovermatcher`, version 2.7.0, code 226.
- Both debug unit suites completed with zero failures and errors. GitHub reported 1,452 tests including 16 skipped. Play reported 1,339 including 12 skipped. Android lint reported 58 warnings and zero errors per debug edition. The source licensing audit passed.
- On API 36 emulator-5554, selected the descriptor in Android’s file picker, toggled on and off in the same process and checked persistence after relaunch. Play refused the same descriptor after an in-place update. Updating back to GitHub restored the imported row. The two debug APKs verified with the same certificate.
- Ran `DlsitePluginDeviceTest` with AndroidJUnitRunner. All three isolated tests passed. Covered fresh and legacy selection, persistent disabled state, manual search, OCR auto-search, cache reuse, master switch, delayed catalogue and cover responses, mixed results and a synthetic saved workbook and DLsite bookmark. The search fixtures run locally.
- Refreshed documentation indexes and ran the documentation consistency check.

## Outstanding work and risks

Live DLsite availability depends on the provider. Network verification against the public service and release signing were outside the local fixture run.

## Next action and references

The owner can toggle the imported **DLsite** switch in **Plugins** and run a catalogue query. Development and import instructions are in `docs/guides/BUNDLED_PLUGINS.md`. The owner decides when to integrate or release the branch. No commit, push, tag, or publication was performed for this implementation.
