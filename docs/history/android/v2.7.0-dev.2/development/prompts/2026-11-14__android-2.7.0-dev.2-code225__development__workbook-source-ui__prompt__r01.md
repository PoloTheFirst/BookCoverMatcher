## Tasks

### A. Separate identity, provenance and availability

Introduce small typed models within the existing architecture, keeping pure state/migration logic testable on the JVM:

- **Session account:** provider, stable provider-issued account key, display label and session generation. Email/name is presentation, never the matching key. Resolve identity using authenticated provider APIs and the existing granted scopes where supported; verify current official API documentation during implementation. Do not parse unvalidated token claims as identity or fetch broad profile data merely for an avatar.
- **Workbook source:** immutable-at-import provider/account binding plus file/document identifier, display location and existing revision metadata. Record the importing account, not the file owner's account. Keep the saved-copy ID independent of source identity. Persist only needed account key/label and source metadata, never credentials. A remembered source label after sign-out is historical provenance, not proof of a current session.
- **Availability observation:** checking/result/reason/checked time, separate from whether a source binding exists and whether an account is signed in. Derive UI from these fields rather than a single misleading linked Boolean. A display path is not a lookup key.

Use optional additive fields and a backward-compatible library migration. Legacy cloud entries with unknown account remain explicitly unverified; never silently bind them to whoever signs in next. Offer an explicit source re-selection/confirmation path when identity cannot be safely recovered. Preserve cross-provider/cross-account duplicate provenance; an identical file must not silently steal an existing entry's link.

### B. Resolve source status accurately

For cloud entries display provider, recorded account, location, last checked time and useful state:

- **Linked** means a source binding exists; distinguish a recent successful check from cached/unchecked information.
- **Unlinked** means no usable source binding. Signed out, session expired, account mismatch and insufficient permission are separate explanations, not deletion.
- **Deleted from drive** is appropriate only with affirmative provider evidence such as a deleted/trashed marker. Generic not-found can also mean lost access; use **File unavailable (missing or inaccessible)** when that is all the provider establishes.
- Offline, timeout, throttling and service errors mean **Unable to check**; retain the previous observation with its age rather than overwriting it as deleted.

Before refresh/update, ensure the active provider/account matches the source binding. Cancel or discard late identity, metadata and download results after sign-out, account switch, viewer change or removal. Scope caches by provider/account/item. Use bounded, asynchronous checks on opening a saved workbook when appropriate and explicit refresh; do not issue a request on every recomposition, load the whole library from the network, or redownload workbooks to check status. Opening an offline saved copy must remain immediate and independent of network success. Update a display path after a verified move when the provider exposes it, otherwise label it last known.

For general local imports, retain the returned document URI and a persistent read grant when the provider supports it. Do not request broad storage access, write permission or access to unrelated files. Keep the copied workbook usable if the grant cannot be retained. Track grant cleanup when no saved source references it, without revoking another entry's access.

Display a truthful device/provider location, filename and source availability. Android content URIs may not expose an absolute filesystem path: show **Location unavailable** or the provider's display location instead of inventing a device path. A document-provider import is not necessarily physically local; label its provider when known. A stable document URI may survive a move. Use **Original moved/deleted or unavailable** only where appropriate, distinguish revoked permission, and do not pretend a generic failure identifies which happened. Existing imports without provenance show **Original location not recorded**, with a re-link option; never substitute the app's private copy path as the original location.

### C. Repair import-to-viewer navigation

Reproduce Google and Microsoft success/duplicate flows. Give **Use it now** one explicit operation that resolves the imported saved-workbook ID and opens that exact entry through the existing viewer path. Preserve scan-source selection if retained by the current action, but await it through a result-bearing operation before dependent navigation; do not call openWorkbookComments immediately after a fire-and-forget useSavedWorkbook.

Keep Home's Saved selector as a scan-source selection action. Avoid changing every useSavedWorkbook caller to navigate. Handle rapid repeated taps, an in-progress operation, missing/deleted/corrupt saved files and cancellation with visible outcomes. Dismiss the import overlay in the successful transition so it cannot hide the viewer, and preserve a useful failure message/retry path. Back returns to the expected library screen. Carry the saved entry ID into the viewer so source metadata cannot be inferred from an ambiguous filename or stale selection.

### D. Compose layout and account labels

Create a reusable source-information presentation for saved workbook cards and the viewer header. Place the compact account/status summary at the upper right where space allows; keep source path accessible below it or in an expandable details area. Long paths/emails must be readable in full on expansion and available to accessibility services. On narrow displays or large fonts, wrap below the title rather than colliding with Rescan/Back or worksheet controls. Status must use text, not color alone.

Keep the provider names on the adjacent import buttons. Add a secondary account line, or **Not signed in**, **Session expired**, **Loading account**, or **Account unavailable** as applicable. Use a single session-state source for buttons and browser dialogs. Clear stale labels on sign-out/account switch. A saved workbook's source account and the button's current account may differ; never overwrite one with the other. Preserve sensible touch targets, equal visual sizing and accessible labels.
